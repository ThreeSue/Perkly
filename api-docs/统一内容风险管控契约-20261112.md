# 统一内容风险管控与平台警告通知（2026-11-12）

本轮只实现后端、迁移及接口文档，Web 和两个移动端页面不在本轮交付范围。兼容 /admin/search-risk，统一前缀 /admin/content-risk。成功响应为 {code:1000,message:"success",data:...}；业务错误通常 HTTP 200 + 非1000 code，认证过滤器可直接返回 HTTP 401/403，客户端同时检查 HTTP 状态与 code。

## 权限与责任主体

读取原文、词库、任务、统计需运营 search:risk:view；修改策略、复核、任务配置需 search:risk:manage；发送警告额外需 notice:send。APP/MERCHANT 即使伪造同名权限也不能读取运营原文。

subjectType + subjectId 联合标识责任账号：APP 顾客；MERCHANT 商家/门店工作人员账号；ADMIN 运营；GUEST 未建立账号身份；SYSTEM 系统或 AI 输出；UNKNOWN 历史记录无法证明提交账号。绝不把 merchantId 当商家登录账号ID。系统输出、游客和无法归责的历史记录不可发送账号警告或自动处罚。

所有检测仅选取公开业务文字、新用户输入及输出文字，不遍历密码、密钥、令牌或整份请求。图片 OCR 和独立评价模块尚未接入，不能写为已覆盖。

## 词库与命中

复用音乐项目 pom.xml / SensitiveWordUtil 实际配置：
- 引擎 com.github.houbb:sensitive-word:0.29.5。
- 真实内置词库 com.github.houbb:sensitive-word-data:1.0.0，非自建 contains 替代。
- 两个依赖为 Apache-2.0；来源 https://github.com/houbb/sensitive-word 与 https://github.com/houbb/sensitive-word-data。音乐项目没有发现额外加载的本地词表；只读核对，未修改音乐项目。
- GET /word-sources 返回有效版本、来源、bundledEnabled、bundledAction、offsetUnit、endExclusive。部署配置 perkly.content-risk.bundled-enabled 默认为 true；内置库仅 REVIEW，不能被场景 BLOCK 策略直接升级为拦截。
- 运营 search_risk_word 优先：全文归一化后精确 ALLOW > 同词自定义启用/停用覆盖内置词 > 内置 REVIEW。同归一化词多条历史配置取最后编号条目；请编辑现有词条，避免重复。
- 自定义 BLOCK/REVIEW 经引擎检测，场景 INHERIT 使用词条级别；场景 REVIEW/BLOCK 只覆盖自定义命中后的动作。停用整个场景则不检测。
- 归一化包括 Unicode NFKC、大小写；内置引擎沿用音乐项目的格式检测能力，关闭数字、邮箱、URL、IPv4 自动检测。
- matchedWords 为去重命中词 JSON 字符串；matchedDetails 为 [{word,mode,source,start,end,matchedText}] JSON 字符串。下标针对 content 原文，以 UTF-16 代码单元计，start 含、end 不含；emoji、全角字符、兼容字符展开均保留原文范围。
- BLOCK 独立事务写风险记录再抛422，即便原业务回滚也保留；REVIEW 允许原业务继续。批量 AI 建议永远为 REVIEW，不自动处罚。

## 记录、复核、审计

- GET /records：page=1、size=20（最大100），可筛 status、scene、source、subjectType、subjectId、兼容 userId、jobId、businessType、businessId、from/to。时间 yyyy-MM-dd HH:mm:ss，北京时间，开始含、结束不含。返回 data={list,total}，不要用 list.length 代替总数。
- GET /records/detail?id：返回 content、matchedWords、matchedDetails、scene、实际 source、subjectType/subjectId、businessType/businessId、mode、status、createTime、operatorId、reason、handledAt、aiAdvice、jobId。原文仅运营有权读取。
- POST /records/resolve {id,status,reason}：PENDING 可转 CONFIRMED / IGNORED / FALSE_POSITIVE。CONFIRMED 表示人工确认需关注，不等于已处罚；IGNORED 表示本次不处理；FALSE_POSITIVE 明确记录规则误报。原因1~200字；缺ID400、重复处理409。误报/忽略不会自动加入白名单，词库修订需单独授权操作。
- GET /audit?page=1&size=20：审计操作人、目标、动作、详情和时间。保留词库、策略、复核、警告、任务、计划配置及APP账号状态变更记录；原工作空间处置沿用原审批历史。
- GET /words；POST /words/save {id?,word,mode:BLOCK|REVIEW|ALLOW,enabled}；POST /words/delete {id}。
- GET /policies => [{scene,enabled,action}]；POST /policies/save {scene,enabled,action:INHERIT|BLOCK|REVIEW}。
- scene：SEARCH / PROFILE / FEEDBACK / CHAT / MERCHANT / STORE / COUPON / NOTICE / AI_INPUT / AI_OUTPUT。

## 工作台四项统计

GET /dashboard => {pendingRecords,pendingAccounts,todayBlocked,bannedAccounts}。

- pendingRecords：全部待处理风险记录数。
- pendingAccounts：待处理记录中 APP/MERCHANT/ADMIN 按主体类型+ID去重，排除游客、SYSTEM、UNKNOWN。
- todayBlocked：北京时间当天 [00:00,次日00:00) 的 BLOCK 记录数，按请求留痕计数，不是账号数；扫描记录为 REVIEW，不混入此数。
- bannedAccounts：user_info.status=0 + base_sys_user.status=0 的当前停用账号数。包含顾客、商家/门店及运营账号；两张账号表分别计数，同一管理账号不会因角色或风险记录数重复计算。包含原账号管理已停用账号，不只统计本模块操作。
- /stats 是旧兼容统计 {pendingRecords,pendingAccounts,confirmedAccounts}；confirmedAccounts 是人工确认记录关联账号，绝不能用作封禁数。

## 原业务处置与封禁

本模块没有绕过业务规则的删除、封号按钮接口。关联 businessType/businessId 供定位，业务下架、撤回、屏蔽等仍走原模块权限和状态校验；无对应业务能力时不能伪造处理成功。

APP账号沿用 POST /admin/user/info/update {id,status:0,banReason:"原因"}；恢复为 {id,status:1}。原 user:info:update 权限继续生效，停用原因最多200字；风险状态修改不会调用这个接口。旧APP令牌在账号停用后立即返回 HTTP403 + {code:403,message:原因}，恢复后重新核对账号和令牌凭据。商家/门店沿用原工作空间 accounts/status 及原授权检查，不新增跨账号处罚权限。

## 平台警告

GET /warnings/preview?riskId => {riskId,subjectType,subjectId,title,content,noticeType}。预览不发送；运营可编辑标题正文与级别。

POST /warnings/send 请求示例：

~~~json
{"riskId":123,"requestId":"warning_review_123_v1","title":"平台内容提醒","content":"请核对本次提交的内容。如有疑问请联系平台。确认仅表示知悉。","noticeType":"STRONG"}
~~~

风险ID为示例，必须使用实际记录。requestId 8~64位字母数字下划线横线；同操作人同键同内容重试复用，不同内容409。接收主体从风险记录确定，不能指定其他收件人。仅 APP/MERCHANT 可收警告；已忽略/误报或缺失真实主体409。标题最多100、正文最多5000字。发送也经过通知内容检测。警告不自动封号。

GET /warnings/receipts?riskId 返回最近100条真实通知回执，不根据前端点击推断已读/确认。

通知 View：
{id,riskId,title,content,noticeType,createTime,readAt,confirmedAt,workspaceNoticeId}。
LIGHT 只读；STRONG 可确认，确认仅表示知悉，不是承认违规。商家/门店复用原 WorkspaceNotice 及收件人回执，businessType=CONTENT_RISK，workspaceNoticeId 是旧通知ID。

## APP本人平台通知六接口

基础路径 /app/platform/notices，Authorization 为本人 APP 令牌，不接受 customerId 指定他人：
- GET /page?pageNumber=1&pageSize=20：{list,total,pageNumber,pageSize}。
- GET /pending：同分页，只含未确认 STRONG，已读但未确认仍在其中。
- GET /detail?id：View，不隐式标读。
- GET /unread：未读整数，含 LIGHT/STRONG。
- POST /read {id}：View，幂等标读。
- POST /confirm {id}：View，STRONG 同时标读和确认；重复确认幂等，LIGHT 返回400。
越权/不存在404；身份错误403；业务拒绝422。被停用账号不能以通知接口绕过认证，停用原因由认证错误提示。

移动端只建议一个消息列表：“平台通知”置顶、门店会话在下面；不增加标签页。本轮没有修改移动端源码，商家和门店继续接原 /merchant/governance/notices。

## 手动有界批量扫描

POST /jobs/start {source,afterId:0,limitCount:50,modelBudget:0} => ContentRiskJob。
source=PROFILE/FEEDBACK/CHAT/MERCHANT/STORE/COUPON/NOTICE/RISKS；limitCount 1~100；modelBudget 0~20。0只词库；正数为该任务最多模型调用次数，也受全局每日预算限制。不会无限分页全库，不在普通业务提交时调用AI。

GET /jobs/status?id（省略取最新）=> {state,task,pendingAccounts}。state=IDLE/QUEUED/RUNNING/COMPLETED/FAILED；task 包含 id、scheduled、source、cursorId、checkedCount、modelCalls、limitCount、modelBudget、phase、error、startedAt、finishedAt。
phase=QUEUED / RULE_SCAN / AI_RUNNING / COMPLETED / FAILED。只有 state=RUNNING 且 phase=AI_RUNNING 才表示真实AI调用；单纯词库扫描不得显示AI运行。
POST /jobs/retry {id} 仅失败任务，从已完成cursor继续，保留已花费预算。modelBudget>0 的任务预算耗尽后保持 FAILED，不推进未检查记录的游标，不降级为词库完成；需要运营检查后创建新的有界任务。modelBudget=0 才是明确的纯词库任务。
完成后通过 GET /records?jobId=实际任务ID 查本批风险。扫描相同业务、主体和内容哈希幂等；已有风险的AI建议可更新，不覆盖人工复核结论。

## 自动定时AI巡检

复用 Spring @Scheduled 和上述批量执行器；数据库 singleton 行锁互斥，不同时启动两批定时任务。默认 enabled=false，不擅自启动付费全库扫描。

GET /schedule 返回持久化配置与状态；POST /schedule/save 请求：

~~~json
{"enabled":false,"intervalMinutes":60,"sources":["RISKS","FEEDBACK"],"batchSize":10,"dailyBudget":20}
~~~

- intervalMinutes=1~10080；sources 为1~8个不重复有效来源；batchSize=1~18；dailyBudget=0~1000，单位是模型调用次数，不是token/金额。每日北京时间零点换日，手动和自动共用预算，调用前行锁计数，失败调用也计入。
- 每批轮换一个来源，按保存的ID游标扫描；当实际检查数量少于批次上限时将该来源游标重置为0，下轮重新检查历史内容，仍受每批和每日预算限制。历史公开资料没有可信创建者时仅 UNKNOWN 待人工核对。
- 这是有界循环回扫，不是按更新时间的即时增量检测；旧内容修改需等待下一轮覆盖，持续新增可能延迟回扫。同步入口仍执行词库检测。
- 状态包含 sourcesJson、cursorsJson、sourceIndex、budgetDate、usedCalls、activeJobId、lastJobId、retryCount、lastRunAt、nextRunAt、lastResult。JSON字符串请解析；lastJobId 可查任务进度及关联结果。无任务时不显示运行。
- 自动批次给最多2次额外调用预算余量，失败最多自动重试2次（原任务/原cursor），每次保留预算消耗；仍失败则停用计划，保留失败任务和游标等待运营检查，不无限重试。
- 正常完成后推进来源游标，记录结果与下次时间；每日预算用完的空闲计划推迟到次日。正在运行时修改计划返回409，避免悄悄改变执行中范围。
- 进程中断的 QUEUED/RUNNING 任务以10分钟无心跳判为失败，不在新实例启动时中断其他健康任务。仍启用的计划按有限重试恢复；人工关闭计划不触发自动付费恢复。
- 开发联调只使用临时/隔离数据；当前开发库计划保持关闭。服务级 perkly.content-risk.scheduler-enabled=false 可停轮询，dispatch-enabled=false 仅用于测试，不作为生产启用方式。
- 模型复用现有 AiProperties 的千问文本模型和密钥，不复制密钥进文档；每次调用最长读取30秒、输出最多400 tokens，模型客户端不另做隐式重试。
