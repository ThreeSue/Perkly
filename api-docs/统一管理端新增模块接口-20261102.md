# 统一管理端新增模块接口

更新：2026-11-02。工程：`cool-admin-vue-8.x`，后端：`cool-admin-java-test`。两个移动端的完整接手契约已并入[总文档第18章](券管家-用户端与商家核销端接口汇总.md)，无需自行拼接历史接口。

## 通用约定

运营用ADMIN令牌及`/admin/**`；商家/门店用MERCHANT令牌及`/merchant/governance/**`，保留X-Workspace。身份取认证上下文，不能提交操作者ID。成功code=1000，非1000显示message；HTTP401/403也须处理。新接口分页为pageNumber/pageSize，data含list/total/pageNumber/pageSize。所有储值金额均为JSON整数分。

新增目录通过WorkspaceInitializer幂等注册；不因重启自动给既有商家上限、岗位或个人加权。运营需在商家功能授权及岗位/个人权限中显式开放新功能。超级管理员可使用运营接口，普通运营账号需对应权限。通知收件和门店共享聊天是登录后公共能力，顶部提供入口；“公共”不扩大消息数据范围或发送权限。

## 通知

运营前缀`/admin/workspace/notices`，商家/门店前缀`/merchant/governance/notices`；发送需notice:send，普通店员不能发送。收件/未读/已读仅本人；已发送/回执仅发送人。具体方法、DTO、错误及重试规则见[站内下级通知接口](站内下级通知接口-20261102.md)。网页`/my/notices`通用入口，授权菜单页`/workspace-admin/notices`或商家/门店对应路由。

## 用户反馈

运营前缀`/admin/support/feedback`，需feedback:manage：

| 方法 | 后缀 | 参数 |
| --- | --- | --- |
| GET | /page | 可选status=PENDING/REPLIED，pageNumber/pageSize |
| GET | /detail | id |
| POST | /reply | id、content，1至2000字 |

列表/详情含customerName、content、images、status、reply、repliedAt、createTime等；图片预览直接用已验证URL。仅单次回复，同一运营同内容重试成功，不同回复/不同处理人覆盖已回复记录返回409。无删除、转派或多轮回复接口。网页`/workspace-admin/feedback`。

## 门店聊天

仅有效STORE工作人员使用`/merchant/governance/chats`；全部本店工作人员可回复，不要求account:manage或运营权限。商家账号、跨门店、跨顾客均被服务端拒绝。顶部`/my/chats`入口无需上级另授发送权，菜单目录可供上级配置显示。

GET/page、GET/messages、POST/send、POST/images/upload的完整参数见总文档18.3。管理网页3秒轮询当前会话，约12秒更新会话列表，隐藏页面暂停请求，卸载清理计时器；按消息ID去重，显示真实发送人名称。不伪造WebSocket、已读回执或已送达状态。

## 平台储值与无券消费账单

运营：`/admin/wallet/accounts`及`/admin/wallet/transactions`，均GET，pageNumber/pageSize，需wallet:manage。accounts含customerName/balance/updateTime；transactions为含优惠、原额、实扣、交易后余额及关联购券/账单ID的账务快照。运营不提供手工改余额或退款接口。

商家/门店：`/merchant/governance/wallet`：

| 方法 | 后缀 | 权限/参数 |
| --- | --- | --- |
| GET | /bills/stores | redeem:use；可开单正常门店名称选项 |
| POST | /bills/create | redeem:use；requestId、storeId、amount、remark可选<=200字 |
| GET | /bills/page | bill:view；pageNumber/pageSize |
| POST | /bills/cancel | redeem:use；id，仅未支付账单 |
| GET | /transactions | bill:view；pageNumber/pageSize |

按门店范围隔离；SELF只查询本人开单相关消费，不能取消他人账单。商家/门店流水不返回顾客个人余额（balanceAfter=null），不包含充值流水。开单成功提供随机billNo给顾客，顾客确认门店/金额后自行试算及支付；工作人员不能直接替顾客扣款。

无券储值账单独立于原优惠券核销账单，原核销流程不变，不能对同笔核销补款重复开单收款。储值购券复用既有发券事务，原订单totalAmount保持原售价；本次实扣/活动优惠以储值流水为准，不将原价交易总额当作储值实收。网页`/workspace-admin/wallet`和商家/门店wallet菜单。

## 支付优惠活动

运营前缀`/admin/wallet/activities`需activity:manage；商家前缀`/merchant/governance/wallet/activities`需activity:apply，且身份必须MERCHANT。门店岗位不能借用商家申请权。网页`/workspace-admin/activities`或`/merchant/activities`。

| 方法 | 后缀 | 参数 |
| --- | --- | --- |
| GET | /stores | 可选择的正常营业门店，id/name/merchantName |
| GET | /page | pageNumber/pageSize；运营全部，商家仅自身且参与门店全部位于当前授权范围内 |
| POST | /create | title、description、startAt、endAt、storeIds；仅运营可传discountRate |
| POST | /review | 仅运营：id、approve、discountRate（通过必填）、note（驳回必填） |
| POST | /offline | id；运营可处理全部，商家仅自己且参与门店全部位于当前授权范围的活动 |

title非空<=100字，description<=5000字；startAt/endAt使用北京时间`yyyy-MM-dd HH:mm:ss`，结束严格晚于开始。商家须选1至100个本商家且有数据授权的正常门店；运营最多指定100店，空列表表示全部正常门店。商家提交PENDING，不接受自设折扣。运营创建直接PUBLISHED；审核通过PUBLISHED、驳回REJECTED；下架OFFLINE。PUBLISHED还须满足起止时间和正常商家门店条件才生效，开始包含、结束不含。

discountRate大于0且小于10，最多两位小数，9表示九折；仅运营设定。按分四舍五入，应付最低1分。多活动不叠加，取优惠最大的单项；同额优先较新。已发生交易保存活动名称/折扣/优惠/余额快照，下架不改历史。不提供原地编辑覆盖历史；驳回/下架后可重新提交新申请。创建请求超时先刷新列表核对，不盲目重复创建。
