# 站内下级通知接口

2026-11-02：代码、规则/模拟依赖HTTP及真实MySQL/Redis令牌链测试已通过，见[完整验证记录](../testing/五模块后端与管理端验证-20261102.md)。移动端只接文档，不修改移动端源码。

## 身份与路径

运营前缀 `/admin/workspace/notices`（ADMIN token）；商家网页、门店网页及核销移动端前缀 `/merchant/governance/notices`（MERCHANT token，沿用登录身份及 X-Workspace）。普通用户 APP token 不可使用：此模块是员工上下级站内通知，不是顾客营销广播。

请求使用现有 `Authorization` 规则；响应成功 `code:1000`，错误显示 `message`。业务错误通常为HTTP 200下的非1000 code，认证过滤器也可能直接返回HTTP 401/403，不只检查HTTP状态。

| 方法 | 后缀 | 用途 |
| --- | --- | --- |
| GET | `/recipients?merchantId=&storeId=&pageNumber=1&pageSize=20` | 查询具体可通知账号，两个筛选ID可省略 |
| POST | `/send` | 发送通知 |
| GET | `/page?sent=false&pageNumber=1&pageSize=20` | 收件箱；sent=true为本人已发送 |
| GET | `/detail?id=99` | 仅接收人可读详情，不自动标为已读 |
| POST | `/read` | `{"id":99}`；仅接收人可标记自己已读 |
| GET | `/unread` | 当前账号未读数量，data为整数 |
| GET | `/receipts?id=99` | 仅发送人可看接收名单及已读时间 |

分页返回 `data:{list:[],total:0,pageNumber:1,pageSize:20}`，pageNumber>=1，pageSize为1至100。接收人返回id、name、username、accountType、merchantId、merchantName、storeId、storeName、roleName，不返回密码/手机号。界面显示名称、岗位，不用ID作展示标题。

发送请求：

```json
{"requestId":"notice_20261102_0001","title":"门店工作安排","content":"请查看本周安排。","recipientIds":[101,102]}
```

requestId：8至64位字母数字下划线短横线；标题非空、最多100字；正文非空、最多5000字；接收人列表1至100项，重复ID去重。成功data为通知ID。超时重试沿用原requestId和内容，同账号同标识返回原ID；更换内容或名单返回409。权限收回后重试也会被拒，不因幂等绕过实时权限。发送整批原子写入，任一接收人非法均不发送。

通知列表/详情：`id,title,content,senderName,createTime,readAt`。正文是纯文字，前端不得当HTML执行；收件箱readAt=null为未读，已发送列表readAt无意义。回执：`recipientId,name,readAt`。重复标记已读保留第一次阅读时间，不支持修改他人阅读状态。时间沿用后端日期序列化，显示按北京时间。

## 授权与边界

- 运营需 `notice:send`（超级管理员例外）；商家和门店需实时获得 `notice:send`，并受商家/门店授权上限控制。新菜单仅注册目录，既有岗位/商家不会因重启自动获得权限，须上级显式授予。
- 运营可选商家账号及门店人员；商家只选本商家授权门店人员；门店管理岗位只选本店普通员工。内置普通店员岗位即使误配发送权限也不能发送。
- 禁用账号、失效岗位、无效商家/门店不进入可选名单；仅选具体人员，不默认广播。
- 查询自己的历史收件、已发送及回执无需继续持有发送权，但登录身份、账号/商家/岗位状态必须有效。
- 当前无附件、撤回、删除、短信或微信订阅推送。顾客移动端无此模块可接路径；核销端可接上述商家前缀的收件接口。
