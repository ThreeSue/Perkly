# 三端统一后台接口

更新日期：2026-10-30。适用统一网页管理后台；用户小程序与商家核销小程序保持各自工程。

## 入口与身份

统一网页工程：`D:/Graduation Project/cool-admin-vue-8.x`，开发端口固定9000，后端8001。登录身份为 PLATFORM（运营）、MERCHANT（商家）、STORE（门店）。三种身份可在同一浏览器三个标签同时登录，分别保存令牌、刷新令牌、账号资料和菜单缓存。

运营沿用 `/admin/base/open/login`、`/admin/base/open/refreshToken`、`/admin/base/comm/person`、`/admin/base/comm/permmenu`。商家与门店沿用 `/merchant/auth/login`、`/merchant/auth/refreshToken`、`/merchant/auth/captcha`、`/merchant/auth/logout`、`/merchant/auth/changePassword`。网页登录及刷新请求增加 `accountType`；请求头携带 `Authorization` 和 `X-Workspace`。历史小程序不传新增身份字段仍可使用原接口。已登录身份与请求头不一致时拒绝访问。

## 统一治理接口

运营前缀 `/admin/workspace`；商家、门店前缀 `/merchant/governance`。以下路径拼接对应前缀。运营须有 `workspace:administration:manage` 或超级管理员身份；下级按每个功能检查权限。下级请求中的 merchantId 不能改变真实所属商家。

| 方法 | 路径 | 用途 / 参数 |
|---|---|---|
| GET | `/me` | 仅商家门店：当前账号、唯一岗位、merchantId/storeId、授权门店、可用默认门店、owner、权限和菜单ID |
| GET | `/permmenu` | 仅商家门店：实际生效的动态菜单和操作权限 |
| POST | `/personal` | 商家门店修改本人姓名，body `{name}`；不接收角色、归属、数据范围 |
| GET | `/merchants` | 有权维护的商家选项 |
| GET | `/stores?merchantId=` | 有权查看的门店选项；运营须指定商家，下级默认本商家 |
| GET | `/catalog` | 下级页面/操作目录；须有账号管理或岗位管理权限，返回目录不代表允许授予其中全部功能 |
| POST | `/roles/list` | 岗位列表；merchantId/accountType/keyword/builtin；包含适用门店和使用账号数 |
| POST | `/roles/save` | 创建或编辑岗位，字段见下文 |
| POST | `/roles/delete` | `{id}`；内置岗位不可删除；仍有账号使用时拒绝并提示人数 |
| GET | `/roles/options?merchantId=&accountType=&storeId=` | 对指定账号类型和门店，返回可分配的有效岗位 |
| POST | `/accounts/list` | 账号列表；merchantId/storeId/accountType/keyword/roleId；仅返回有权管理的账号，不返回密码 |
| POST | `/accounts/preview` | 与账号保存相同结构；返回岗位名称、生效菜单 effectiveMenus、受上级限制而暂不生效的 suppressedMenus；只读 |
| POST | `/accounts/save` | 创建、编辑、改岗、重置密码；一号一岗位，禁止自行提权 |
| POST | `/accounts/status` | `{id,status:0或1}`；停用保留账号和历史，并使原会话失效 |
| GET | `/grants?subjectType=&subjectId=` | MERCHANT商家上限或STORE门店上限及其原配置 |
| POST | `/grants/save` | `{subjectType,subjectId,menuIds:[]}`；完整保存授权快照，空数组表示全部关闭 |
| GET | `/settings?merchantId=` | 默认门店和营业执照号；商家默认自身 |
| POST | `/settings?merchantId=` | `{defaultStoreId:null或门店ID,licenseNumber:null或编号}`；默认可不设，已有编号不能覆盖 |

列表接口当前返回数组，由页面执行门店/岗位/状态等组合筛选，不使用分页响应对象。业务门店、优惠券、购券订单和消费账单沿用原分页接口。

## 账号与岗位结构

岗位保存字段：`id?、merchantId?、name、label、remark?、accountType(MERCHANT/STORE)、status(0/1)、menuIds[]、grantMenuIds[]、applicableStoreIds[]`。

- menuIds：岗位本人可使用的页面与操作。
- grantMenuIds：允许给下级授予的功能；与本人使用权限不同，仍受上级上限限制。
- applicableStoreIds：岗位可分配给哪些门店。留空表示所属范围内全部；店长自定义岗位始终限制在本店。它不是员工可查看数据的范围。
- 内置共享岗位仅运营可改，商家/店长创建自定义岗位。共享岗位保存前页面提示影响人数。

账号保存字段：`id?、merchantId?、storeId?、username、name、password?、accountType、roleId、status、storeScope、storeIds[]、allowMenuIds[]、denyMenuIds[]`。

- 新账号使用11位登录手机号。旧账号保留原用户名，不允许通过编辑改名或改变商家/账号类型。
- roleId是单值；无多角色组合。修改岗位时页面展示新旧有效权限和个人增减设置，再确认保存。
- MERCHANT的数据范围为ALL或SELECTED；指定门店由老板划分。SELECTED空数组意味着没有门店数据。只有老板/运营可授予ALL。
- STORE绑定唯一门店。STORE范围可看本店记录，SELF仅本人经办记录；任何门店账号不能查看其他门店。
- allowMenuIds为单账号额外开放，denyMenuIds为单账号禁止；禁止优先，再与商家及门店上限取交集。
- 修改员工岗位、归属、状态或密码后旧会话失效。个人改姓名只更新显示姓名，不改权限归属。

## 授权收回与恢复

运营设置商家功能上限，商家在可授予范围内设置门店上限，店长在上级授予范围内维护本店岗位和员工。关闭父级功能不清掉子级配置，恢复时沿用仍保留的配置；已主动撤销的子级配置不自动补回。

保存授权会锁定主体，并用当前锁定读取校验新增项；上级暂未开放时允许保留原有配置或移除，不允许重新增加已撤销的隐藏权限。接口每次请求检查生效权限；页面刷新、重新进入或返回标签页时会刷新授权上下文。

平台系统管理的菜单编辑增加“使用身份”：空值为运营，MERCHANT为商家，STORE为门店，SHARED为商家/门店共用。新增页面须先有实际页面文件和正确viewPath，再配置菜单并逐级授权。新增业务操作可以用准确路由权限，例如 `/merchant/custom/page` 对应 `custom:page`；新增业务接口自身仍须执行商家和门店数据隔离。

## 复用业务与补充字段

- 门店、优惠券、购券订单继续使用 `/merchant/workspace/*`。消费账单继续使用 `/merchant/consumption/*`，验券使用 `/merchant/redemption/inspect`。
- 金额券：验券→输入金额→prepare生成订单→确认线下补款→confirm核销。套餐/体验/兑换券：验券→确认权益→redeemContent自动生成订单并核销。网络结果不明确时保留原requestId及账单，查询或重试原操作。
- 门店状态：0禁用、1营业、2停业、3关闭。停业可后台查看和维护，不能核销；用户端详情可显示停业，附近推荐默认排除停业。商家可恢复停业；禁用解除、关闭后恢复由运营处理。
- 空门店删除须无员工、券、核销、消费账单引用，且未设为默认门店。已有历史记录保留，不能级联删除。离职员工只停用。
- 默认门店可空，不创建空门店，不自动指定第一家；写入与核销明确选择有权营业门店。
- 营业执照号为15或18位字母数字。游客入驻提交增加可选兼容字段licenseNumber，新核销小程序表单要求填写；开通时复制并锁定。历史旧客户端未传编号时，旧商家可一次性补录；编号已有值后运营、商家均不能覆盖。
- 地图增加 `/admin/merchant/map/translateGps` 和 `/merchant/workspace/map/translateGps`，GET参数longitude/latitude；将浏览器GPS坐标转换成GCJ-02。前端地图选点器支持手填坐标应用和用户主动获取当前位置，最终仍须核对地址并确认保存。定位依赖浏览器授权及腾讯服务配置/额度。
- 岗位、账号、授权、商家设置和门店状态变更在现有audit_record保存操作人与脱敏快照，不保存账号密码。

本轮不新增结算费率、结算周期、退款、提现、发货或AI业务。

## 运营菜单整理补充（2026-10-30）

运营侧栏按教师结构重排，商家管理内集中商家/门店目录、商家功能授权、岗位和账号入口；系统权限管理维护运营账号、菜单和角色。既有菜单ID、业务接口、角色授权关系及商家/门店目录保持。

既有`POST /admin/base/sys/menu/list`增加可选`menuAudience`筛选：`PLATFORM`仅运营目录，`BUSINESS`为MERCHANT/STORE/SHARED目录，未传或`ALL`沿用完整目录。该字段仅筛选展示，实际接口权限按原鉴权执行。新`/workspace-admin/menus`是网页菜单维护路由，不是新增业务API；复用原菜单CRUD及排序接口。
