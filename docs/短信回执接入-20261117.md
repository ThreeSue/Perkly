# 短信回执自动同步

## 数据来源

- SEND：本应用发送请求与阿里云受理结果；受理不等于送达。
- VERIFY：本应用核验记录。同一个发送流水成功核验多次，仅第一条 VERIFIED 计入通过数，后续为 VERIFIED_REPEAT。
- sms_receipt：阿里云 DypnsSmsVerifyReport 回执，流水号唯一约束，手机号仅保留脱敏形式。
- 官网历史汇总不会导入，也不会填充到本地统计中；公开接口空响应不代表历史发送量为零。

## 部署

先执行 `deploy/sms-receipts-20261117.sql`，新增独立表，不更改原短信发送表。

运行后端的进程配置以下环境变量：

```text
PERKLY_SMS_RECEIPTS_ENABLED=true
PERKLY_SMS_RECEIPTS_QUEUE=控制台显示的完整队列名称
PERKLY_SMS_RECEIPTS_REGION=cn-hangzhou
```

继续使用既有 `ALIBABA_CLOUD_ACCESS_KEY_ID` 和 `ALIBABA_CLOUD_ACCESS_KEY_SECRET`。
目前实现对应已确认的华东1；其他地域显式报 UNSUPPORTED_REGION，不猜测云通信服务端点。
配置项位于 application-local.yml；生产配置需同样映射上述环境变量，或者设置 sms-auth.receipts.* 属性。
未启用时页面明确显示“回执消费未启用”。变更运行环境后重启后端。

云通信队列采用服务托管账号，通过 Dybaseapi 的 QueryTokenForMnsQueue 换取临时凭证；不是自行创建的普通 MNS 队列。
不要根据队列名中的账号编号拼接 MNS endpoint，也不要未经核验授予 AliyunMNSFullAccess。
授权失败时记录供应商错误码，不记录凭证、原始回执正文、手机号或 receipt handle。

官方参考：
- https://help.aliyun.com/zh/pnvs/developer-reference/simple-message-queue-receipt-demo/
- https://help.aliyun.com/zh/pnvs/developer-reference/message-receipts/

## 可靠性与统计口径

- 独立单线程消费者，长轮询 5 秒，空队列视为正常连接。
- 临时凭证在到期前两分钟刷新；固定 HTTPS 服务端点，连接和读取超时受限。
- 事务提交成功后才删除队列消息；数据库异常或确认失败时留待重投。
- 重复流水不会增加统计，新于已保存回执时间的供应商结果允许修正旧状态。
- 消费异常指数退避，最长 300 秒。页面显示连续失败状态与错误码，服务日志输出安全错误码。
- 格式异常消息不直接丢弃，会显示错误并等待处理；阿里云队列有保留时限，持续异常需要及时运维，不能保证无限期重投。
- 未匹配本应用发送流水的账号级回执保存在回执表，不计入本应用发送统计；迟到回执和晚写入的发送流水查询时自动匹配。
- 送达、失败、等待回执按原发送日期范围计算，只统计本应用 ACCEPTED 流水；核验统计按核验发生日期计算。
- 页面每 15 秒刷新，切到后台或离开页面停止有效轮询。回执存在运营商延迟，页面不承诺秒级送达状态。

## 管理接口

`GET /admin/sms/usage/receipts?days=1|7|30`，需要平台身份与 `sms:usage:view`。

返回 `delivered`、`failed`、`pending`、`recordingSince` 和 `sync`。
`sync.state`：DISABLED / CONNECTING / RUNNING / ERROR；`lastPoll` 是最近成功轮询时间，`lastReceipt` 是本进程最近成功处理消息时间，服务重启后重新记录。
`recordingSince` 为现存第一条本地发送事件日期，不表示该日期前的历史已同步。

既有 `/events` 增加 `deliveryResult` 和 `reportedAt`；纯后端与管理端改动，移动端无需修改接口。

## 验收

先确认 RUNNING，再使用授权测试手机号发送并核验一次，验证 ACCEPTED → DELIVERED，以及 VERIFIED 去重。
开发/自动化测试禁止实际发送短信；SmsUsageIntegrationTest 仅允许固定隔离库，显式关闭回执消费者。
历史官网汇总对账仍待确认受支持查询接口，不作为本功能已完成的能力。
