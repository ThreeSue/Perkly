- 缩小局部光斑、降低透镜大面积泛白、移除未选中项的悬停亮块。
- H5可见页面鼠标移动均改变光照方向，距离越远强度越低；不移动选中项。按帧合并，无常驻空转动画；页面隐藏和卸载清理监听及帧请求。
- 拖动本身产生约0–19%伸长、0–11%压缩、方向性倾斜及最多0.1格视觉延迟，去掉重复CSS缓动；松手按实际触点选择后弹簧收敛。窗口失焦取消，鼠标移出胶囊仍能拖动/松手。
- 小程序保留原触摸链路和平台无关数学，不引入window、SVG或WebGL依赖。两端业务与接口均未修改。

当前仍是半透明材质和动态高光/形变模拟，**没有真实背景折射**。不能仅凭这些改动宣称完成液态玻璃。

## 真正液态玻璃需要什么

1. **可实时采样的背景**：取得玻璃下方文字、图片、滚动内容的当前像素，并与滚动/页面切换同步。背景若是单色，即使计算折射也缺少可见参照。
2. **曲面与折射场**：按胶囊形状、厚度、表面法线、折射强度计算像素偏移；边缘产生可辨认的弯曲、局部放大和收缩。SVG displacement或GPU shader是可选计算手段；单纯透明度、亮度、饱和度不产生此效果。
3. **光照与运动耦合**：局部镜面高光、薄亮边/暗边、可控的色散与焦散应响应曲面/速度，折射场随果冻形变同步，不能只缩放白色图层。无需照搬全部物理光学才能达到可信的产品视觉。
4. **平台渲染路径与性能预算**：H5可以先验证SVG displacement背板滤镜；Safari存在兼容问题。WebGL可计算折射，但Canvas不会自动得到后方DOM纹理，还需解决背景来源。小程序需要先验证当前渲染器是否有合适的背板采样能力；仅有Canvas/WebGL支持不足以证明能折射任意底层view。必要时将受影响背景区域与玻璃放入同一受控渲染场景，须评估改动范围与维护成本。

推荐先做隔离技术样机：在真实滚动的文字/图片上测试可辨认折射、果冻形变同步及滚动同步，再在iOS/Android微信真机验证帧率、功耗、层级与可触达性；通过后接入。兼容降级必须明确标为半透明效果，不以模拟冒充折射。现有项目不需要后端新增接口或更换业务框架；实际采样方案尚未完成验证，不能承诺当前uni-app x下所有微信设备均能获得任意背景的同等折射。

需要确认的工程条件是目标微信/基础库版本、当前渲染模式、至少一台iOS和一台Android测试设备，以及低端机性能底线。AppID仅在开发者工具/真机调试时按正常项目配置使用，不需要提供账号密码或短信验证码。

## 本次验证

- 9项玻璃数学/组件控制器测试，连同既有23项共32项通过；43个SFC结构语法、格式检查通过。严格UI静态审计0错误0警告。
- HBuilderX 5.26：客户端16页、商家10页微信小程序开发编译成功。客户端生成JS未包含window/requestAnimationFrame/startTracking。
- 实际H5：胶囊外鼠标从中心光斑改变为约20%横向/17%纵向；同次拖动采样观察到约13–16%伸长、8–9%压缩，松手进入“我的”。拖出胶囊上方松手正确进入“我的券”。375 CSS px视口无横向溢出，导航标签完整；键盘导航保持可用。
- 小程序仅编译验证，尚未真机验收手势/性能。无真实折射样机、未声称苹果同等效果。本次不涉及后端业务验收。
