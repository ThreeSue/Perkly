# H5底部液态导航接入 · 2026-10-23

## 实现范围

客户端与商家端的H5主导航已接入实时背景位移折射；沿用五端独立应用、原有三个tab路由、switchTab和全部业务接口。微信小程序保留此前半透明导航和原有运动，不接入SVG、背板滤镜或H5放大/色散效果。白色光斑、白色反光渐变均未恢复。

## 材质与交互

- 外壳与选中透镜在同一背板采样平面处理，绕开旧深色父层隔离背景的问题。曲面位移场使页面背景在边缘弯曲，不使用模糊。蓝灰底色和深色标签保证阅读，平坦单色背景上的折射本来就不明显。
- 按住或滑动时，选中透镜沿阻尼弹簧放大：纵向增加约58%，横向乘0.88，再叠加速度形变。透镜上下可超出外壳约3–7px；松手弹性收回，跨tab继承运动。
- 背板裁切使用外壳与透镜的SVG联合轮廓，允许透镜露出外壳；按钮的语义、点击区域、顺序、文字布局不随外观变形移动。
- 选中曲面上的R/G/B通道采用略有差异的真实背景采样偏移，形成薄边色散；另有0.8px、低透明度的环境彩边，使单色背景也略有边缘色相。它不是白色高光，也不把整块透镜染成彩色。
- 图片位移场仅在导航尺寸变化时生成；移动时更新SVG位置/尺寸/采样强度，不逐帧Canvas绘制或PNG编码。扩张弹簧650ms内停算，导航位移弹簧900ms内停算；静止无常驻动画循环。
- 增强仅针对当前已验证的Chromium内核，其他浏览器使用可读的既有半透明回退。减少透明度/强制高对比时停用折射；减少动态效果时不放大、不回弹。未承诺Safari/Firefox真实折射。

## 手机模拟模式误回退修复 · 2026-10-23

用户截图的环境是Edge设备工具中的iPhone SE 375×667。修复前在该既有标签页读取到`.floating-nav`深色底`rgba(48,75,101,0.9)`，SVG滤镜数量为0。共享渲染器原先只允许UA包含Chrome/Chromium/Edg；iPhone模拟UA报告Safari，因此初始化直接返回null。设备模拟可以覆盖UA，并不切换实际渲染内核，参见[Chrome设备模拟说明](https://developer.chrome.com/docs/devtools/device-mode)。

修复内容：

- 优先识别Chromium运行时对象与Client Hints品牌，结合背板滤镜语法支持；UA仅作为备用。设备模拟不再因Safari UA被错误关闭增强；真实WebKit/Firefox继续回退，不把CSS语法支持当成SVG背板实际渲染支持。
- 两端导航的显示/隐藏代次隔离：取消已经隐藏页面的nextTick初始化；旧渲染器的迟到回调不能修改新实例的就绪状态。
- 将扩张、倾斜也纳入折射更新监听，避免选中项外形变化而折射轮廓没有同步。
- 追加热更新资源清理：SVG记录导航归属和清理函数，新实例挂载时先销毁同一导航的旧观察器、监听器与滤镜；模块支持热替换时也主动清理，滤镜ID另做全局占用检查。

验证：`pnpm check`（43 SFC）、shared/client/merchant/trade/glass共36项测试、格式及diff检查通过；严格UI审计和DESIGN lint无错误/警告。新增回归覆盖iPhone模拟UA、真实WebKit/Firefox与无滤镜能力回退；两端生产组件控制器覆盖隐藏前未完成初始化、旧回调隔离、放大/倾斜同步。HBuilderX客户端16页、商家10页微信开发编译通过，生成导航组件不包含H5折射/SVG/backdrop-filter代码。

在原Edge iPhone SE标签页刷新后，个人中心、首页、券包均恢复`has-refraction`，键盘切换有效，375×667无横向溢出；正常切页稳定后保留1个滤镜。开发热更新期间发现的旧SVG残留也已修复：重新加载共享模块、再分别热更新两端组件后，两端均保持`has-refraction`且各仅1个滤镜。真实iPhone Safari仍按兼容策略回退，本次未作真机验收。修复截图：[iPhone SE个人中心](./06-iphone-se-fix.jpg)。
