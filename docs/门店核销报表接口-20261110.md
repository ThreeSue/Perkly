# 门店核销独立报表接口（2026-11-10）

普通业务报表，无模型调用、AI开关、密钥或AI额度依赖。旧AI统计接口委托普通报表服务。只读，不导出、不修改移动端。

## 接口

POST `/merchant/reports/redemptions/query`，Authorization沿用门店员工登录。R包装的data为Report。

```json
{"period":"LAST_7_DAYS","startDate":null,"endDate":null,"operatorId":null,"orderNo":null,"couponName":null,"page":1,"size":20}
```

日期TODAY/LAST_7_DAYS/LAST_30_DAYS/CUSTOM，默认今天；上海自然日，结束日包含，最多366日且不能未来。单天按小时（24桶），多天按天，补零。page>=1，size1至100。orderNo/couponName采用包含匹配，区分大小写；同时影响汇总、趋势、分布、人员统计和明细。无历史关联订单的记录无法匹配订单号或券名。

响应字段：
- range：实际起止日期；storeId/operatorId为后端限制后的范围。
- summary：successfulRedemptions成功流水数；linkedOrders为筛选集中可确认的不同关联消费单数；knownConsumptionYuan已知去重消费金额；unknownAmountGroups未知/冲突消费金额组数；knownDiscountYuan实际核销优惠合计；unknownDiscountRecords优惠缺失流水数；failedAttempts=null（无可靠失败流水）。
- trend：time/count，单天time为YYYY-MM-DDTHH:00，多天YYYY-MM-DD。
- types：type/count/percentage，占比0至100保留两位，空结果为空数组；类型来自消费单历史couponType，不查询当前券模板，旧记录缺少关联时UNKNOWN。
- people：id/name/count，为当前筛选有成功流水的员工统计，历史删除账号显示“历史员工（账号已删除）”。
- list：id/orderId/orderNo/couponName/couponType/operatorId/operatorName/redeemedAt/consumptionYuan/discountYuan；时间为现有Jackson日期编码，前端按上海时区显示；无历史依据的名称/订单为null，不能猜。
- total/page/size：完整筛选条数及当前页。稳定排序按核销流水ID倒序，不按金额排序。

GET `/merchant/reports/redemptions/operators` 返回可筛选人员数组id/name/count，count固定0仅为复用人员DTO，不代表该人核销次数。包含本店现有成员及本店历史核销员工，不以停用状态过滤。SELF仅本人。统计请使用query.people。

## 权限

复用bill:view。必须有效STORE员工、岗位有效、唯一绑定有效门店；OWNER不可访问。权限检查沿用WorkspaceAuthorization.ownRecordsOnly的现有数据范围契约。本人范围省略人员自动本人，指定他人403；本店范围省略人员为全部，指定人员只收窄本店数据，跨店人员无法查询跨店数据。无storeId参数。

## 金额与历史口径

金额均元。成功流水coupon_redemption.discount_amount是核销时实际计算的优惠，不由票面猜测，按流水求和；缺失显式计数，全部缺失返回null。消费金额按有效关联消费订单去重，同组金额缺失或不一致计未知。历史无有效关联单按独立流水一组，不计关联订单数。空集金额为0；部分未知返回已知合计并展示未知数，不能当作完整总额。消费金额不是营业收入。

消费单的couponName/couponType是历史快照字段；不回查当前模板。人员姓名使用现存账号姓名，删除后仅展示历史占位，不声称保留离职前姓名快照。

## 实现与限制

查询使用MyBatis-Flex实体getter条件，500条ID游标分批读取，按批获取关联订单；在可重复读事务中查询，不取当前页冒充全量，也没有扫描截断。原始流水不全量载入内存；去重订单组、人员、时间桶仍占聚合内存，超大历史量需数据库分组优化。每次分页也执行完整聚合，暂不提供大规模压测承诺。

未部署或重启服务，未进行真实HTTP/数据库集成验收；当前单元测试验证模拟查询。真实跨店、历史人员选项、并发新增下分页及数据库时区仍需集成验证，不能据此声明全部验收。
