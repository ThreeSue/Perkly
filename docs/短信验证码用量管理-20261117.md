# 短信验证码用量管理

运营入口为「系统设置 → 消息与验证 → 短信验证码」。平台岗位使用 `sms:usage:view` 查看，另授予 `sms:usage:manage` 后可修改单号码每日发送上限。

## 统计和限额

- 日常管理使用「用量概览」「使用明细」「发送设置」三个页签；这三项不需要额外开通云端统计或回执队列权限。
- 概览显示当前生效的每日上限、最短间隔、本地记录起始日期，以及发送失败、结果待确认、去重核验通过、核验未通过或异常。统计读取本地真实业务流水，不补造官网历史记录。
- 送达回执和账号级账单放在「云端查询（可选）」中，点击后才请求，不再随主概览每 15 秒自动查询回执。

- 单号码默认每日 5 次，调整范围为 1–30 次。登录、注册、找回密码、绑定手机、修改密码和商家入驻共享额度，按北京时间自然日计算。
- 图片验证码通过后，后端在向阿里云发送前预占额度。阿里云明确拒绝、超时或结果未知也占用此额度。超过日上限或 60 秒发送间隔的请求记为拦截，有效期内已收到的验证码仍可核验。
- 本地统计提供发送、拦截、核验和限额修改明细，统计从启用日起累计。手机号仅显示脱敏值。未登录记录可在实际完成用户业务后关联已核验用户；商家入驻仅记手机号核验，不自动关联用户账号。
- 可用 `sms-auth.daily-warning-threshold` 和 `sms-auth.monthly-warning-threshold` 配置平台发送请求的预警值，默认 0 表示关闭。达到预警值时在概览提示，发送继续按号码限额执行。

## 后端部署

1. 在实际使用的 MySQL 库执行 `deploy/sms-usage-20261117.sql`。脚本只新增短信使用相关表和默认策略，可重复执行。部署新后端前先执行迁移。
2. 启动新后端和管理前端，运营账号刷新会话后进入页面。多实例须使用一致的 `sms-auth.usage-hmac-key`，省略时沿用一致的 JWT 签名密钥。保持密钥稳定可延续同一号码的计数。
3. 可选的「云端查询」使用已有的号码认证服务凭据查询。阿里云子账号需有 `dypns:QueryGateVerifyStatisticPublic` 和 `dypns:QueryGateVerifyBillingPublic` 权限。该处是云账号范围，可能包含同一账号的其他应用。未开通不影响本地次数管理。

阿里云接口见[短信认证用量](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-querygateverifystatisticpublic)及[短信认证月账单](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-querygateverifybillingpublic)。

## 运营接口

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/admin/sms/usage/overview` | `days` 为 1、7 或 30 |
| GET | `/admin/sms/usage/events` | `days`、`scene`、`kind`、`result`、`page`、`size` |
| GET / POST | `/admin/sms/usage/limits` | POST 使用 JSON `{"dailyLimit":5}` |
| GET | `/admin/sms/usage/cloud/usage` | `days` 为 1、7 或 30 |
| GET | `/admin/sms/usage/cloud/billing` | `month` 格式为 `YYYY-MM` |
