# 首页轮播广告：后端与运营端

更新：2026-10-27。本次仅实现后端和运营端，不修改用户端。

## 数据和展示规则

新表 `home_banner`，复用框架BaseEntity的ID、创建和更新时间。

| 字段 | 说明 |
| --- | --- |
| id | 广告ID |
| title | 名称，1至100字 |
| imageUrl | 图片地址，最多1000字符；支持HTTP/HTTPS或后端根相对地址，例如 `/uploads/banner.png` |
| jumpType | NONE不跳转、STORE门店详情、COUPON优惠券详情、WEB网页 |
| jumpTarget | 门店ID或优惠券ID的字符串，或HTTP/HTTPS网页地址；NONE时为null |
| sort | 0至999999，越小越靠前，同值按ID升序 |
| status | 0停用、1启用；新增默认停用 |
| startTime / endTime | 可空，格式 `yyyy-MM-dd HH:mm:ss`，北京时间，精确到秒 |
| createTime / updateTime | 框架维护 |

公开列表须同时满足：启用、开始时间为空或已到达、结束时间为空或尚未到达。
时间区间为 **[startTime, endTime)**。两者都填写时结束须晚于开始；支持仅开始、仅结束和永久展示。
STORE目标要求门店及所属商家均启用；COUPON目标复用现有公开优惠券查询条件，包括当前规则版本审核通过且已在平台渠道上架、存在适用营业门店。
目标下架、停用或删除后自动从公开列表排除，不删除广告记录。重新有效后可再次符合展示条件。
优惠券目标的可见性与当前公开优惠券详情接口一致，未另外把“售罄/尚未开始领购”等仍可查看详情的状态视为删除。
WEB地址仅允许有效HTTP/HTTPS，不允许javascript、协议相对地址或带用户名密码的地址。
图片保存地址，不把图片文件或base64写入表。

## 通用响应与认证

响应沿用 `{ "code":1000, "message":"success", "data":... }`。
运营接口沿用 `Authorization` 请求头，直接传运营访问Token。业务错误检查code及message，不能只看HTTP状态。
超级管理员admin可管理；普通运营人员须获得对应菜单操作权限。商家或用户Token不能调用运营接口。

## 运营接口

前缀 `/admin/home/banner`。

| 方法与后缀 | 用途 | 权限 |
| --- | --- | --- |
| POST `/page` | 分页列表 | home:banner:page |
| GET `/info?id=1` | 详情 | home:banner:info |
| POST `/add` | 新增 | home:banner:add |
| POST `/update` | 完整编辑 | home:banner:update |
| POST `/status` | 启用、停用 | home:banner:status |
| POST `/delete` | 单条或批量删除 | home:banner:delete |
| GET `/targetOptions` | 搜索可展示目标 | home:banner:targetOptions |

### 分页

```json
{"page":1,"size":20,"keyword":"周末","status":1,"jumpType":"STORE"}
```

page默认1，范围1至100000；size默认20，范围1至100；其余筛选可省略或为null。
返回 `data.list`、`data.pagination`，pagination内含page、size、total（总条数）。
列表及详情除表字段外增加：

- `targetName`：目标名称或网页地址；目标删除时明确显示已删除。
- `displayStateText`：已停用、待开始、已结束、目标不可用、展示中。

### 新增与编辑

```json
{
  "title":"周末门店推荐",
  "imageUrl":"https://example.com/banner.jpg",
  "jumpType":"STORE",
  "jumpTarget":"101",
  "sort":0,
  "status":0,
  "startTime":"2026-11-01 00:00:00",
  "endTime":"2026-11-08 00:00:00"
}
```

新增不能指定id，成功 `data` 为新ID数值。编辑在请求中增加id，成功data为true。
编辑为完整表单提交：title、imageUrl、jumpType、sort、status须填写；startTime、endTime可明确传null清除已有时间；NONE自动清除旧jumpTarget。
不要用完整编辑接口只修改status，启停使用专用接口。
启用时目标须当前可公开查看；停用广告可保存已存在但暂时未公开的目标。
不接受客户端覆盖创建时间。

### 启停与删除

```json
{"id":1,"status":1}
```

停用不要求旧目标仍有效，可以立即停止广告；启用重新验证目标。

```json
{"ids":[1,2]}
```

删除1至100条；先在事务中核对全部ID，任一不存在则不删除其余记录。
只删除广告，不删除上传文件、门店或优惠券。

### 目标选项

`GET /admin/home/banner/targetOptions?type=STORE&keyword=咖啡&page=1`

type须为STORE或COUPON；keyword可选、最多100字；page默认1，每页30条。
返回分页结构，每项包含id、name、merchantName。前端显示名称与商家名称，内部保存ID。
复用当前公开门店/优惠券过滤逻辑，不返回停用门店或未上架优惠券作为新选项。
编辑时原目标不在新选项内，仍通过详情的targetName回显，不自动替换为其他目标。

## 用户端预留接口

`GET /app/home/banner/list`，允许游客，不需要携带Authorization。

成功data为数组：

```json
[
  {"id":1,"title":"周末门店推荐","imageUrl":"https://example.com/banner.jpg","jumpType":"STORE","jumpTarget":"101","sort":0}
]
```

只返回当前有效广告，按排序取最多10条。在目标有效性过滤后取前10条，不会因前面的失效广告而遗漏后面的有效广告。
无广告返回空数组，后续用户端应隐藏广告位，不使用虚构广告填充。
用户端后续根据jumpType自行跳转详情或网页；本次未接入用户端轮播组件或导航。
WEB最终如何打开须由对应平台前端处理，小程序网页还需符合其业务域名配置。
