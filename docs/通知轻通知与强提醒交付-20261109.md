# 通知轻通知与强提醒交付

日期：2026-11-09。实现范围：现有工作人员通知后端、统一管理端、移动端接口文档。先前AI改动全部保留，没有回滚或覆盖移动端AI目录；未提交推送或打包Docker。

## 已实施规则

- LIGHT轻通知为默认，只保留收件箱和未读提示；STRONG强提醒向已选接收人显示发送人、时间、标题及纯文本正文，点击“我知道了”确认。不是短信、微信订阅或系统推送。
- 通知类型保存在原通知表；confirmedAt保存在原接收记录，各人隔离。确认同时已读，原/read仅已读，不影响待确认提醒。确认以行锁串行化，重复保留首次确认时间；不自动代他人确认。
- 历史null类型兼容为LIGHT，原自动活动通知继续LIGHT。非法类型拒绝；同requestId改通知类型视为不同请求，返回409。原上下级发送、岗位授权和整批接收人校验不变。
- 所有登录身份挂载同一个接收组件，复用30秒前台补拉及登录/回前台刷新。旧通知先展示，一次一个；不切换页面、不卸载编辑表单。确认失败保留当前弹窗并允许重试。
- 支持Web Locks的浏览器同账号多标签页协调展示，storage事件同步确认并重查服务端。无锁支持/网络异常不保证严格只弹一次；服务器确认幂等。账号切换和退出清空本地队列，旧token请求结果不覆盖新状态。
- 发送表单可选两种类型，默认轻通知；强提醒有弹窗提示。列表、详情和发送回执展示类型及确认信息。

## 接口和数据库

完整接入协议：[通知轻通知与强提醒](../api-docs/通知轻通知与强提醒-20261109.md)。已有send新增noticeType，已有列表/详情新增noticeType、confirmedAt，回执新增confirmedAt；新增GET pending和POST confirm，两个原身份前缀复用。

增量字段：workspace_notice.notice_type、workspace_notice_recipient.confirmed_at。开发环境AutoTable开启时随后端重启添加；其他环境先执行[幂等迁移](../deploy/notice-types-20261109.sql)。迁移不删除通知。主开发进程没有由本轮重启，主开发库没有由验收脚本主动迁移；隔离回归库已应用并验证。

核销移动端按接口接入强提醒弹窗；旧客户端仍能读通知但不会弹窗确认。普通顾客移动端仍没有工作人员通知入口，不能使用MERCHANT接口冒充员工。两个移动端前端均未修改。

## 使用与发布

站内通知 → 发送通知 → 选择轻通知/强提醒 → 选择具体人员 → 确认发送。强提醒确认后可在已发送 → 查看回执查看各人的时间。部署顺序：迁移/AutoTable → 重启新后端 → 部署管理端构建并刷新。无需新增角色权限；原本没有发送权的账号不会因这次更新获得发送权。
