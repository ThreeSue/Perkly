# 入驻与门店分离：后端变更说明

更新日期：2026-10-26。采用用户确认的方案①，本轮只修改后端与接口文档，不修改任何前端。

## 统一流程

客户端或核销端申请商家 → 运营审核 → 领取营业码 → 商家网页端验证同一手机号、开通OWNER账号 → OWNER登录后创建门店并录入地址、GCJ-02经纬度、店长/员工账号。

## 接口变化

- `/app/merchant/onboarding/submit`、`resubmit` 从请求DTO移除address。有效申请资料为merchantName、categoryId、contactName、选填introduction；联系电话从onboardingToken确定。requestId、applicationNo等业务参数规则不变。
- 新快照不包含address。重提保留历史轮次，新轮次不再保存旧地址。
- 为兼容尚未修改的前端，JSON多传address时显式忽略，不校验、不存储，也不参与requestId幂等比较；新调用方应停止发送。历史申请携带相同有效资料可继续用原requestId重试。
- `/merchant/auth/activate` 不把历史申请地址复制到商家资料。开通仍只创建商家及OWNER，不自动建店。
- 原历史审核快照和已有商家/门店数据不批量修改，不删表、不迁移数据库结构。旧账号密码申请重提兼容入口保持已有规则。
- 后续建店仍使用 `/merchant/workspace/store/save`，门店地址必填，坐标成对传入并校验范围；地图维护接口不变。

## 验证

四组回归共44项通过，失败0、错误0、跳过0：GuestMerchantOnboardingIntegrationTest 16项、MerchantOnboardingIntegrationTest 5项、MerchantWorkspaceIsolationTest 14项、MerchantLocationIntegrationTest 9项。

新增覆盖旧页面多传地址被忽略、无地址申请与重提、保留历史快照、历史申请幂等重试、历史地址激活不迁入商家且不自动建店。原申请归属、一次开通、OWNER登录、权限隔离和门店地图回归通过。

日志：`logs/test/onboarding-without-address-20261026.log`；JUnit报告：`target/surefire-reports/`。使用模拟短信，事务回滚及已有独立并发测试清理方式，没有发送真实短信。没有启动或重启常驻后端服务。

## 部署及前端交接

部署或重启加载新代码后生效。本轮未提交或推送Git。

前端保持当前状态，之后单独删除入驻表单的地址字段和必填校验；在前端改动前页面仍可能要求用户填地址，但新后端会忽略该值。网页营业码开通、客户端入驻入口的接入进度不因本次后端变更而视为完成。

完整请求契约见《游客商家入驻与开通接口.md》，工作区api-docs的单独文档和移动端接口汇总已同步更新。
