## “运行就自动建库”核实

Perkly的`application-local.yml`启用了`auto-table.enable: true`，实体扫描范围是`com.cool.**.entity`。启动会为已有实体维护对应表，本机`merchant_info`、`store`、`coupon_template`等表确实存在。

它不会从数据库规划Markdown推导缺失的实体，也不会仅因为Mapper写了某个表名就自动建该表。`cool.initData: true`只加载已提供的初始化JSON；目前这份代码没有商家分类/商品/券数据初始化内容。上次Spring应用完整启动后，以下依赖表仍缺失：

- 商品：`product`、`product_store`；商品模块源代码也缺失。本批`plan.json`中为每家商家准备了一个商品/服务名称，但**只是待导入计划，尚未写入商品表**。
- 券展示/规则关联：`coupon_store`、`coupon_product`、`coupon_publication`。因此即使已有12条券模板，公开券查询仍然报错。
- 交易/核销：`purchase_order`、`purchase_order_item`、`customer_coupon`、`coupon_redemption`。源代码和路由检查也没有对应交易/核销Controller。
