## 记录权限接入要求

- 用户已确定的策略：员工在当前授权门店只看本人完成的核销；店长直接查看该门店所有员工核销，不提供本人/店长视图切换。
- `utils/merchant-records.ts` 的 employee/manager 为前端标准化值，不是后端角色码。正式认证适配器必须依据后端有效身份及逐店授权映射，不能把现契约中的 OWNER、顾客/管理员 Token 或 URL 参数猜作店长。
- `stores/session.ts` 默认上下文为空，只有未来正式认证适配器才能赋予已验证上下文；没有新增运行时假登录。账号/门店切换整体替换授权，退出/过期/撤销授权清空；正式列表接入时必须清私有列表、让旧响应失效。
- 后端必须以 Token 推导商家与操作员，校验当前门店权限；普通员工即便删改操作员/门店/范围参数，也只能查询本人。店长也不能跨商家、跨未授权门店。列表、详情、统计、搜索均应用同一范围，不能下载全店数据再前端过滤。
- 现有 `POST /merchant/redemption/page` 只说明商家级分页和可选门店，不足以保证上述员工隔离；在身份、授权和筛选契约补齐前继续不调用，不新增猜测字段/端点。
