# 核销端 AI 聊天接口与接入说明（2026-11-09）

## 本次实现

新增独立门店聊天：意图解析 → 服务端权限校验 → 只读查询 → 自然回答；支持会话条件延续、快捷建议和清除会话。已有5个只读数据接口继续保留。没有修改移动端UI、用户端助手、管理端CouponAssistant或共享AI连接配置。

公共鉴权仅在WorkspaceAuthorization.checkRoute中增加7个精确路由，复用bill:view并继续执行原context检查，不开放任意前缀。服务层重新检查STORE员工身份、有效岗位、商家、唯一门店及本人数据范围。查询券额外要求coupon:view，预检额外要求redeem:use。OWNER不能使用。无新增权限菜单注册依赖。

## 两个聊天接口

沿用商家登录Authorization请求头。不是用户端令牌，也不是商家OWNER令牌。

### POST /merchant/ai/assistant/chat

```json
{"sessionId":null,"message":"今天我核销了几张？","couponId":null,"orderId":null,"code":null}
```

返回现有R包装，data示例结构（示意，非真实模型记录）：
```json
{"sessionId":"服务器随机会话ID","message":"今天暂无成功核销。","action":"STATISTICS","conditions":{"period":"TODAY","startDate":null,"endDate":null,"operatorId":123,"couponId":null,"orderId":null,"keyword":null},"cards":{"successfulRedemptions":0,"failedAttempts":null,"knownConsumptionYuan":0,"unknownAmountGroups":0},"suggestions":["改查近七天","改查今天"],"degraded":false,"operation":"READ_ONLY"}
```

后续发送相同sessionId和新message。message必填1至1000字符。couponId/orderId为页面选中目标的待校验标识，不能增加权限；code是独立扫码上下文字段，绝不放进聊天文字。前端不能传valid/confirmed等结果替代后端预检。code只用于当前请求，不保存会话；再次验券需重新提供。

cards是按action区分的真实查询数据（并非固定数组）：STATISTICS为统计对象；RECORDS为list/total/partial；ORDER为精简消费单卡片；COUPONS为原分页/详情的白名单投影；INSPECT为白名单预检结果或valid=false/reason。ASK/UNSUPPORTED时为空数组。前端按action渲染，不把所有cards视为同一类型。

operation仅READ_ONLY/NONE，不会返回写操作成功。degraded=true表示查询完成但自然语言总结失败，此时仍显示真实cards。模型识别失败返回503，可重试，不返回假结果。

### DELETE /merchant/ai/assistant/session?sessionId=...

使用原登录令牌清除；成功返回R.ok。未知、过期或别的账号/门店/登录令牌的会话返回409。会话保存在单实例内存，30分钟空闲过期、最多2000个；服务重启后失效。不保存长期画像。令牌仅存SHA256指纹。退出后旧令牌由既有登录鉴权失效，新令牌不能继续旧会话。多实例需会话存储迁移或粘性路由。

## 支持范围与实际限制

- STATISTICS：今天/近7天/近30天/自选日期，人员ID进一步缩小范围。店员不能看他人；有全店范围的岗位可查全店或指定人员。姓名无法确定ID时澄清，不猜同名员工。
- RECORDS：相同日期与人员过滤，最近20条及总数/partial，不把当前页当全量统计。
- COUPONS：本店授权可见券，关键词、券ID、真实规则；首20条候选。可见券可能未发布，不等于可使用。其他筛选暂不支持。
- ORDER：根据消费单ID查询详情；不查询购券订单，不支持按自然订单号搜索。
- INSPECT：调用权威trade.inspect，依据真实失败原因解释。仅预检，不核销。业务失败原因可显示，401/403继续抛出。
- 不提供核销、支付、撤销、权限修改、通知或任何其他写入。模型没有写工具。

统计用Asia/Shanghai自然日、包含结束日；近7/30天含今天。自选范围最多366日且不能晚于今天。成功核销全量查询；同账单金额去重；无账单ID的旧流水各算一组。缺失/冲突金额为未知组，全部未知金额为null，空集为0。failedAttempts始终null（暂无可靠失败流水）。消费金额不能称收入。统计金额字段knownConsumptionYuan单位元，订单Cents字段单位分；券规则沿用原业务字段单位，前端需按原券接口约定显示。应用内全量聚合需要后续大数据量优化，不做截断估计。

## 开关、额度及部署集成

复用AiProperties的BAILIAN_API_KEY、baseUrl和textModel。没有将图像额度策略混作聊天额度。新增独立Spring配置：

```properties
perkly.ai.merchant-chat.enabled=false
perkly.ai.merchant-chat.daily-limit=0
```

默认关闭，未配置返回503，绝不默认无限次。运维经确认设置enabled=true及正数daily-limit（每账号每天按上海自然日，包含失败请求）。当前额度计数为单进程内存，重启清零，不宣称持久账单限额；多实例/严格生产计费应替换为Redis或数据库原子限额。控制台配置页面未开发，默认值未替用户确认。

## 其他只读接口

统一前缀/merchant/ai/assistant，POST：statistics（period/startDate/endDate/operatorId）、coupons（couponId或keyword）、inspect（code）、order（orderId）、records（无请求体，首20条）。统计日期枚举TODAY/LAST_7_DAYS/LAST_30_DAYS/CUSTOM。

错误：401登录失效；403权限/身份/范围不足；400请求无效；409会话失效（前端清空sessionId重试新会话）；429额度用尽；503未配置/模型服务异常。遵守现有R与全局异常处理约定，不只凭HTTP200判成功。

## 移动端操作注意事项

只需接chat/session；数据接口可供专用查询界面复用。账号退出或切换时清空本地sessionId和卡片；不要自己拼接历史assistant文本；历史条件由服务器管理。不要发送扫码完整内容作为message。收到ASK显示回答与suggestions；收到UNSUPPORTED只提示不能执行，不触发任何写接口。AI返回的文字不应成为核销授权依据。
