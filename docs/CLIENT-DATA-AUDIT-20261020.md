## 本地存储检查

- 未发现订单、购物车、券、核销或搜索结果等业务状态写入本地存储；也未发现 `localStorage` / `sessionStorage` 调用。
- Cool Unix 仍在客户端保存服务端签发的 access/refresh Token，以及微信授权流程中的短时 `mpCode`，用于恢复认证会话/继续授权。这些是客户端请求凭据，不是业务缓存，服务端仍负责签发、刷新和校验。
- 已移除 Cool Unix `userInfo` 的持久化快照：启动时清理旧缓存；个人资料通过 `/app/user/info/person` 从后端读取，只留在当前运行内存。个人资料修改请求成功后再次读取服务端资料。
- 首页地点名称、搜索词和表单输入仅保留在当前页面运行内存；地点不缓存精确坐标、不上传。

## 当前真实接口边界与后端缺口

已提供的真实接口资料覆盖普通用户验证码/短信登录/密码登录/注册、用户资料，以及管理员账号和商家分类管理。管理员分类接口不能用于顾客端。

后续收到的门店/优惠券浏览契约已整理至 `BACKEND-DISCOVERY-API-20261020.md`，并接入 `api/discovery.ts`。首页、门店列表与详情、优惠券列表与详情已使用后端只读接口；接入状态与剩余联调条件见 `CLIENT-DISCOVERY-INTEGRATION-20261020.md`。购券订单创建/查询、后端模拟支付、支付后按数量发券、券包与券详情、核销记录等接口仍待提供。旧微信登录组件中的 `/app/user/login/mini` 不在现有联调文档里，该组件已删除。

数据库规划定义 `purchase_order`、`purchase_order_item`、`customer_coupon` 和 `coupon_redemption`，不含购物车、真实支付交易或退款表。因此，后端报告按“订单 → 后端模拟支付 → 发券 → 核销”列能力缺口；不应把早期 API 草案中的购物车、真实微信支付和退款路径当作 3.0 需求。
