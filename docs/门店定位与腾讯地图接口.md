# 门店定位与腾讯地图新增接口

日期：2026-10-24。仅后端；已有门店、商家、优惠券接口保持不变。

## 通用约定

- 响应沿用 `{ "code": 1000, "message": "success", "data": ... }`。业务失败检查 `code` 和 `message`，不能只检查 HTTP 200。
- 经纬度统一使用 **GCJ-02**；字段 `longitude` 表示经度，`latitude` 表示纬度。腾讯接口内部的 `lat,lng` 顺序已由后端转换，前端按字段名传参。
- 需要登录的接口：请求头 `Authorization` 直接填写对应端的访问 Token，沿用现有项目约定。刷新 Token 不能调用业务接口。
- 不要求所有历史门店立即填写坐标。不自动把文字地址转换后写入，不伪造门店位置。需人工核对地图后保存。
- 普通门店列表和详情保持原行为；空坐标门店不参与附近查询，但在管理地图数据中明确列为待补录。

## 1. 运营端门店分布数据

`POST /admin/merchant/store/map`，运营账号登录。请求体可省略或传 `{}`。

```json
{
  "keyword": "咖啡",
  "merchantId": 1,
  "storeTypeId": 1,
  "status": 1,
  "located": true
}
```

所有筛选项均可省略。`keyword` 按门店名称、所属商家名称、门店地址匹配；最多100字。
`storeTypeId` 对应公共门店类型 `store_type.id`，不是商家分类。
`status` 为0停用、1营业，省略则两种都包含；`located` 为true只查已定位、false只查待补录，省略则两种都包含。

成功时 `data`：

```json
{
  "coordinateSystem": "GCJ-02",
  "total": 2,
  "locatedCount": 1,
  "unlocatedCount": 1,
  "list": [
    {
      "id": 101,
      "name": "示例门店",
      "merchantId": 1,
      "merchantName": "示例商家",
      "storeTypeId": 1,
      "storeTypeName": "直营店",
      "cover": null,
      "address": "福建省福州市示例路1号",
      "phone": "13800000001",
      "businessHours": "09:00-21:00",
      "longitude": 119.2,
      "latitude": 26.1,
      "status": 1,
      "statusText": "营业中",
      "located": true,
      "locationStateText": "已设置位置",
      "distanceMeters": null
    },
    {
      "id": 102,
      "name": "待补录示例门店",
      "merchantId": 1,
      "merchantName": "示例商家",
      "storeTypeId": 1,
      "storeTypeName": "直营店",
      "address": "示例路2号",
      "longitude": null,
      "latitude": null,
      "status": 0,
      "statusText": "已停用",
      "located": false,
      "locationStateText": "待补充位置"
    }
  ]
}
```

示例第二项省略了部分公共字段。计数均对应**本次筛选后的结果**。
这是地图专用的全量列表，不读取普通分页的第一页，也不会静默限制为20或100条。
前端只将 `located=true` 的门店绘制为地图标记；其余放入待补录列表。
单边坐标缺失或历史越界坐标也视为待补录。`0,0` 是合法坐标，不用是否为零判断是否定位。
停用门店、停用商家旗下门店在运营管理范围内仍可查看。
当前适合本项目数据规模；大规模部署需要再扩展视野范围查询和聚合策略。

## 2. 商家端门店分布数据

`POST /merchant/workspace/store/map`，商家主账号登录。

请求及响应结构与运营端一致。**范围从登录账号确定**，即使请求体传入其他 `merchantId` 也不会越权查询。
包含自己全部营业、停用和待补录门店；现有店员权限范围不扩大。

## 3. 补录或修改位置

| 端 | 接口 | 权限 |
| --- | --- | --- |
| 运营 | `POST /admin/merchant/store/location/update` | 运营访问权限 |
| 商家 | `POST /merchant/workspace/store/location/update` | 主账号，仅自己名下门店 |

```json
{
  "id": 101,
  "address": "福建省福州市核对后的详细地址",
  "longitude": 119.1234567,
  "latitude": 26.1234567
}
```

四个字段必填。地址1至500字；经度-180至180、纬度-90至90，建议保留最多7位小数。
成功返回 `data: true`。行锁内核对归属，仅修改地址和坐标，复用已有门店业务校验。
本接口用于设置位置，不提供清空坐标操作。
新增门店仍使用已有 `add` / 商家 `store/save` 接口并一并传入地址、经纬度。
历史门店未补录时无须改动其他资料，也不需要数据库新增字段或迁移。

## 4. 用户端附近营业门店

`POST /app/merchant/store/nearby`，公开查询，不要求用户登录。

```json
{
  "longitude": 119.2,
  "latitude": 26.1,
  "radiusMeters": 10000,
  "page": 1,
  "size": 20,
  "keyword": "咖啡",
  "merchantId": 1,
  "categoryId": 2
}
```

经纬度必填。其余可选：半径默认10000米，范围1至100000米；page默认1且须大于0；size默认20，范围1至100。
`merchantId` 为所属商家；`categoryId` 沿用原公开列表含义，为商家分类ID，同时包含其直接下级分类。
关键词最多100字，匹配门店、商家名称和地址。

成功 `data` 为：

```json
{
  "list": [],
  "pagination": { "page": 1, "size": 20, "total": 0 }
}
```

`list` 每项与上方 `StorePoint` 字段一致，额外提供数值 `distanceMeters`（米，未取整），是球面直线距离而非步行/驾车路线距离。
`pagination.total` 是符合条件的门店总条数。数据库先筛选半径、按距离升序排序、同距离按门店ID升序，再分页。
只包含有效坐标、门店营业且商家启用的数据。没有坐标或没有附近门店时返回空列表，不自动混入远处门店。
未取得用户位置时，前端继续调用原有普通门店分页接口。
距离计算使用本地数据库与MyBatis-Flex，不消耗腾讯周边搜索接口配额。

## 5. 腾讯地点搜索与地址解析

三端共用功能，但路径与登录身份对应：

| 路径前缀 | 身份 |
| --- | --- |
| `/admin/merchant/map` | 运营账号 |
| `/merchant/workspace/map` | 商家主账号 |
| `/app/merchant/map` | 已登录用户 |

以下每个后缀均支持这三个前缀。腾讯地图的Key、签名密钥、sig不会返回给前端。
这些是腾讯地点库查询，与查询本平台门店分布/附近门店不同。
小程序游客仍可使用原生选址；本组会消耗腾讯配额的接口要求登录。

### 地点输入提示

`GET {前缀}/suggest?keyword=闽侯县人民政府&region=福州`

`keyword` 必填，1至100字；`region` 可选，最多50字。提供城市时仅返回该城市的地点；省略时全国搜索。
每次最多20条，为选址提示，不承诺返回所有地点。

```json
{
  "coordinateSystem": "GCJ-02",
  "total": 1,
  "list": [
    {
      "id": "腾讯POI标识",
      "title": "地点名称",
      "address": "详细地址",
      "longitude": 119.2,
      "latitude": 26.1,
      "province": "福建省",
      "city": "福州市",
      "district": "闽侯县"
    }
  ]
}
```

前端输入建议防抖300至500毫秒并避免重复请求。

### 地址转坐标

`GET {前缀}/geocode?address=福建省福州市闽侯县人民政府&region=福州`

address必填，1至500字；region可选，最多50字。只解析，不自动保存门店。需要人工核对地图位置。

### 坐标转地址

`GET {前缀}/reverseGeocode?longitude=119.2&latitude=26.1`

经纬度均必填，范围同位置补录。两种解析成功的 `data`：

```json
{
  "coordinateSystem": "GCJ-02",
  "address": "地址文字",
  "longitude": 119.2,
  "latitude": 26.1,
  "province": "福建省",
  "city": "福州市",
  "district": "闽侯县"
}
```

地址转坐标时address保留输入地址，逆地址解析时为腾讯返回的地址。部分区划字段可能为空。
失败时显示后端message，不要求前端自己拼接腾讯请求URL；网络超时、授权/配额异常不会透传包含凭证的上游异常。

## 6. 配置和部署

后端启动工作目录默认是 `cool-admin-java-test`，读取忽略Git的 `config/tencent-map.local.yml`：

```yaml
tencent-map:
  key: "后端服务Key"
  secret-key: "签名校验SK"
```

启动工作目录不同时，通过环境变量 `TENCENT_MAP_CONFIG` 指定该文件的绝对路径。
没有配置时门店分布、附近计算、位置补录仍能工作；只有腾讯地点服务会明确提示尚未配置。
变更凭证后重启后端。网页地图Key仍只供前端加载地图，后端SK不得放入VITE变量或提交Git。
