# 客户端开发入口

## 当前版本（2026-10-20）

客户端已回滚至 Cool Unix 框架后重建首页，业务路由当前共12个；`pages/demo` 有72个、`pages/template` 有10个 `.uvue` 页面保留作 Cool Unix 演示/模板参考，均未在 `pages.json` 注册。它们仍包含模板自带的商品、评论、地址及旧购物车样例，不属于当前可访问的券管家业务页面。未接入的偏好、通知、客服/关于和简介编辑页面已从客户端运行范围移除。后续 2026-10-13 的样例商品、购物车实现记录在下方历史部分只作参考。

首页入口为外卖、团购、电影演出、民宿；搜索使用 Cool Unix `cl-input`、`cl-button`，地点使用 `uni.chooseLocation`。客户端已接入游客可用的行业分类、门店分页/详情、优惠券分页/详情接口；页面按真实 DTO 显示门店和优惠券，不回退到本地样例，也不调用管理员分类接口。四个服务入口中，“团购”进入优惠券列表，其余进入门店发现；后端尚无这些服务场景的独立筛选字段。登录框无默认手机号或验证码；未提供 API 契约前隐藏未确认的微信登录入口。

3.0 数据库规划没有购物车；`apps/client/api/cart.ts` 进程内示例已移除。购券订单、模拟支付、发券与核销状态必须由后端产生；“我的券”页在顾客券包 API 提供前说明待接入，不展示样例券。客户端不持久化订单/券等业务状态；Cool Unix 仍在本机保存服务端签发的 access/refresh Token 和微信授权短时码以恢复认证。用户资料快照不再持久化：启动时清理旧缓存，资料通过 `/app/user/info/person` 从后端读取并仅保留在运行内存，资料修改成功后重新读取。昵称/性别使用已知 `updatePerson` 字段；头像上传服务契约未确认，当前不提供头像编辑。

接口覆盖和待后端确认的能力见 [接口覆盖与后端需求报告](./接口覆盖与后端需求报告.md)；门店与优惠券浏览接入情况和剩余条件见 [接入记录](./CLIENT-DISCOVERY-INTEGRATION-20261020.md)。此前客户端检查、H5及小程序编译记录属于发现页接口接入前的状态；本轮未请求真实后端，也未进行HBuilderX编译或微信真机验收。布局美术规划和三张静态样稿见 [本轮规划](./client-design-20261020/功能清理与布局美术规划.md)。

## 历史实现（回滚前）

客户端主要面向微信小程序，H5 作为辅助预览；在 HBuilderX 打开 `apps/client`。三项导航是首页、我的券、我的，消费记录从我的进入。

## 页面模板来源

| 业务页面/组件 | 原模板 | 保留的结构 |
| --- | --- | --- |
| home | pages/index/home.uvue | group、cl-row/cl-col 栅格入口及分组列表 |
| profile | pages/index/my.uvue | 居中头像身份区、栅格入口、带图标列表 |
| list / merchants / client-category-layout | pages/template/shop/goods-category.uvue | 左侧分类、右侧卡片内容 |
| coupon-detail / client-coupon-item | pages/template/shop/goods-detail/index.uvue、info.uvue | 信息卡片、金额/标签区、资料行、底部操作栏 |
| login | pages/user/login.uvue | 居中身份区、表单内容区 |

原模板保留，业务适配放在 pages/business。删除与券业务无关的示例商品、购物车、支付、假统计与远程认证；没有新增品牌视觉。商家详情、券包和消费记录等原模板没有直接对应页面，使用同一组件库与页面约定。

## 服务及演示边界

- 页面统一调用 api/index.ts；领域模型位于 types/business.ts，独立本地实现为 mocks/client.js。
- 浏览商家和券无需登录。领取要求本地昵称登录，成功后返回并继续领取，同一昵称同一券只领一次。不同昵称的演示身份数据隔离。
- 会话及演示数据保存在内存，刷新重置。消费记录不创建订单、不支付、不与其他端同步。真实接口地址与 AppID 留空。
- 列表支持搜索、分类、分页、加载/空数据/错误重试和过期响应保护；退出使在途个人请求失效。
