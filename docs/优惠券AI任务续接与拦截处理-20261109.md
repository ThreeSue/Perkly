# 优惠券 AI 任务续接与拦截处理

本轮依据真实对话调整管理端优惠券助手。目标是让模型在任务上下文中判断下一步，而不是只在固定字段里提取答案。本地代码尚未推送、部署或打包Docker，用户端AI独立模块未修改。

## 处理路径

1. 模型接收原待办、最新用户消息与上轮问题，判断补充、改口、取消或新任务。
2. 后端使用现有业务服务检查建议。修改预览增加发布状态检查，不能到确认时才第一次发现券正在审核或上架。
3. 修改/启停受阻后，将真实拦截原因、当前券数据、原计划、可修改字段和当前有权执行的前置步骤交给模型。模型可提出最小替代值、前置步骤或继续提问。
4. 建议重新经过业务校验；每轮最多一次自动修复规划。建议仍不合法就保留原任务追问，不循环调用模型或偷偷执行。
5. 用户核对新的完整变更并点击确认，前置步骤与原修改在同一事务执行；任何一步失败全部回滚。修改已上架券不会自动恢复上架或替代平台审核。
6. 确认时数据变动或业务拦截，由控制器在事务回滚后返回新的`recovery`答复。前端回到对话展示新方案，不能将其显示为执行成功；新方案需要再次确认。

`CouponAssistantRecovery`是模型建议模块，不直接持有写入工具。实际执行仍由既有业务服务负责。目前可自动规划的发布前置步骤为同一券的`UNPUBLISH`与`WITHDRAW`，仅在对应状态和当前权限允许时可用。金额、有效期、限领、库存、内容和门店等建议复用已有字段目录及校验，没有为每一种用户说法添加新的业务执行器。

## 对话改口和创建

- 追问中的文字先重新判断意图，不再一律按原字段解析。`AFTER_ISSUE`与`FIXED`切换会移除旧待办中另一种有效期的字段及追问。
- “取消修改，打开封面编辑”可以结束旧待办并给出授权后的原编辑入口。模型说明生成失败时保留可用入口，页面明确提示说明未生成，不冒充模型回复。
- 创建缺少参数时保存已有草稿需求；商家名称不唯一时返回商家选项，或者等页面选择商家后继续。商家选项与优惠券候选项分开，不把商家ID当成券ID。
- 用户明确授权“你来拟定优惠/详情”时，模型可起草建议方案，仍须人工核对保存。没有授权时不凭空决定售价、菜品数量或业务日期。
- 模型回复不得把已核实支持的待修改字段说成“不支持”，但这一检查不能保证所有语义错误都被发现。

## 接口兼容变化

- `/chat`原结构保留。`clarification.type`增加`REPAIR`、`CREATE`、`MERCHANT`，仍通过`answer.token`、`answer.value`或文字续答。
- `/confirm`成功保持原响应；可重新规划的业务失败返回`data.recovery`（与`/chat`的Reply相同）。此响应表示旧确认未成功，不是部分成功。权限错误、过期令牌、无法恢复的操作仍返回错误。
- 缓存内Pending增加前置步骤列表；前置步骤不可由客户端直接指定为执行请求。旧缓存缺少该属性时按空列表处理。

### 商家创建草稿回复误拦截修复

发现 `CouponAssistantNarrator` 的事实来源只包含“草稿已准备好”，没有包含 `Reply.draft` 的内容。因此模型自然回复中引用草稿的售价、项目数量、有效天数等真实值，也会被当成未知数字拦截；重试后若模型省略数字则可能通过。

现在生成回复及事实核对共用待核对草稿事实，包含券名、商家、优惠规则、金额、项目数量、限领与有效天数。草稿属于尚未保存的预览，保留对虚构数字、遗漏目标券名及谎称已保存的检查。正常文案仍由模型生成。

若说明模型仍返回503，返回已授权的结构化草稿和空说明，前端明确显示“系统提示：草稿已保留，尚未保存”，让用户继续核对。该降级不执行保存，不将固定提示伪装成模型回答。

最终代码定向回归5项全部通过（0失败、0错误、0跳过），包含两条真实商家创建请求各重复3次、草稿保留降级、错误数字和未保存状态校验，结果见 `logs/test/assistant-draft-narration-final.log`。真实模型用例要求说明非空且通过事实核对，未用降级掩盖生成失败。前端 `npm run type-check` 通过。上述为接口与模型回归，不表示整套助手验收或真实页面验收已经全部通过。

## 边界

### 授权拟定优惠规则的创建入口修复

截图中的“工作日引流满减券，门槛和减免由你建议”暴露了另一处遗漏：创建入口仅在券名、券型或售价缺失时调用方案拟定，基础字段齐全时跳过了规则拟定。现改为每次创建由建议模块判断用户是否授权拟定，再合并建议与已有需求；明确给定的值优先，没有授权则保留追问，不按固定金额默认补全。

`assistant-delegated-rules-v2.log` 定向测试3项通过：基础字段齐全仍能建议门槛和减免、明确的免费/7天/限领1张不被建议覆盖、未授权时继续追问、商家选择续接；其中截图原句在真实模型上连续3次生成完整未保存草稿及非空说明。首轮曾出现说明降级（草稿保留），记录在 `assistant-delegated-rules.log`，不据此宣称模型不存在偶发失败。正常创建多一次授权与方案判断的模型调用。

这是现有优惠券工具范围内的有限规划和续接，不是任意接口、任意SQL或全系统自主代理。不能自动提权、替用户审核、修改已发放数量、删除历史关联或跨商家操作。缺少经营决策时必须询问；不承诺任意语言均能理解或所有异常都可恢复。发布/删除等尚未接入完整修复规划的操作会明确拦截，不应宣称全部业务均已自主处理。
