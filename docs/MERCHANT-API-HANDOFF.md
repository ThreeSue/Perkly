# 商家端功能与后端接口交接

更新：2026-10-21。需求依据：本次用户提供的商家核销前端功能图、《券管家3.0_数据库表规划(1).md》及 `用户端购券券包与商家核销接口.md`。用户明确将本图用于 apps/merchant；apps/verification 仍为独立应用，本轮未合并或改写。仅负责前端，未实现后端或数据库。

## 交付与接口现状

2026-10-21 用户开工后明确限定：本轮只开发新接口文档的用户部分，三个商家核销接口暂缓。本轮尝试的商家接口适配已撤回，商家端保持原有待接入状态；下文保留接口能力分析，不能视作已经接入。未来商家工作仍需正式登录/会话/授权门店契约。

商家端为独立 Cool Unix / uni-app x 工程，使用既有 cl-page、cl-button、cl-form、cl-form-item、cl-input、cl-textarea。主题沿用 client 的黄色 #ffe23f、浅灰 #f5f5f5、白卡与 680px 内容宽度。底部导航：工作台、核销记录、我的。没有安装另一套 UI 或后端框架。

当前 docs/BACKEND-API-20261013.md 只确认顾客账号、平台管理员账号与管理员分类接口，未确认它们可用于商家员工。本轮不调用这些接口替代员工认证，不向商家端注入管理员/顾客 Token。新增接口文档现已提供商家核销预检、确认和本商家核销流水契约；但员工/商家会话和可操作门店查询仍缺，且本次接口文档要求使用商家 Token、现阶段沿用启用的 `OWNER` 账号。因此这三项当前仍未接入前端，不能用硬编码门店或假身份绕过前置条件。其它商家业务接口仍待交付。

后端可以直接在前端工程补接，也可提供契约后由前端开发者接入。统一入口：apps/merchant/api/index.ts；当前 merchantCapabilities 标记缺口，requestMerchantCapability 对缺失能力明确 reject，不返回伪造数据。此入口不是可用的网络实现；接入时需新增真实请求、数据映射及相应页面的加载/失败/重试/空结果/分页状态，不能只把按钮 disabled 去掉。

## 逐项交接清单

下列为业务能力需求，不是已确认 URL 或 DTO；不从数据库列名自动生成接口路径。字段名称、类型、枚举、金额单位、时间格式、分页及权限码由后端提供正式契约。

| M02 stores | home：选择本人获授权门店；profile：授权列表 | sys_user_store、store、merchant_info | 当前账号可访问门店列表；当前门店上下文规则，切换后重新校验数据范围；禁用/撤销授权的响应 |
| M03 dashboard | home：今日核销数量 | coupon_redemption | 当前门店/当前员工今日汇总；明确统计口径、业务时区、日期边界；未知不能显示 0 |

## 当前可操作和暂不可操作

- 可浏览全部页面；工作台功能跳转、底部导航、本人/店长视图切换、券码/查券关键词临时输入及清空可用。上述切换不授予角色权限，也不加载私有数据。
- 登录表单、授权门店、按时间/类型筛选、建券、审核记录和反馈均待接入；核销预检/确认/基础流水虽然已有契约，但当前因商家会话和门店上下文缺失而未接入，提交保持禁用，不存草稿，不显示成功。券类型/状态/权限枚举未确定，不提供虚构选项。
- 二维码扫描暂未启用：未验证员工与门店前不申请相机权限；接口接入后按 H5 / 微信小程序能力接入 uni.scanCode，取消保留手输内容，失败给出文字原因；不自动把二维码 URL 当作可信券码。
- 核销记录明细、券详情和审核详情没有真实记录作为入口，当前保留说明；后续按契约实现详情展示，不能用表结构拼假数据。
- 不开放本地演示登录、不使用 mock、不保存业务数据、不造统计、券码、员工或门店。

## 接入顺序与验收

1. 先交付 M01/M02/M13，建立商家端独立身份、会话过期处理和可操作门店上下文。退出/过期清空私有列表和当前门店，使在途响应失效；不能恢复上个员工的私有数据。
2. 在商家 Token 和已授权门店可用后接 M04/M05：扫码或手输→后端预检→展示返回的权益与试算→店员明确确认→服务端再次校验并核销。按钮请求期间防重复、失败保留可纠正输入；按新契约处理核销流水 ID/时间，不自行标记成功。
3. 接 M06 基础分页流水；M03/M07 的店长/店员统计、按操作员/时间/券类型筛选及记录详情需补契约。异步防过期响应，区分加载/错误/无结果；未授权不拉取数据。
4. 接 M09/M11/M12；建券字段按正式类型规则渲染，失败保留输入；成功收到真实返回后再进入审核列表。反馈不得自行假报提交成功。
5. 后端验收：跨商家/门店隔离、撤销授权、普通店员访问店长接口、过期/作废/已使用券、最低消费门槛、并发重复核销、网络超时重试、版本快照、审核驳回原因。前端不能替代事务/幂等约束。

生产 API 域名、微信 AppID 和独立员工账号/门店授权方案尚未确认；新核销契约规定二维码解码结果应为完整券码，但相机扫描仍需在获得商家身份和门店上下文后接入。前端本次未接新接口，不代表真实员工登录、核销或审核已可用。
