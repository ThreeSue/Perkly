# 下级通知：实施边界与接口草案

更新日期：2026-11-02。当前通知实体、后端接口、统一网页已实现；本文件保留原需求与实施边界，不再作为“尚未开发”状态依据。实际契约见[站内下级通知接口](../api-docs/站内下级通知接口-20261102.md)，当前验收见[开发进度](后续模块开发进度-20261102.md)。下方“建议/草案URL”仅是历史设计，不能覆盖实际接口文档。

## 已确认范围

运营可通知商家或直接通知门店；商家可通知本商家旗下门店；门店可通知本店员工；普通店员不能向同店其他员工发送通知。通知只能向下级发送，具体岗位的发送权限由授权控制。先实现后端，再接统一管理网页；用户端与核销端不修改，完成后提供接口文档给移动端负责人。

## 2026-11-02 已确认的接收人和发送权限

- 运营或商家向门店发通知时，由发送人选择具体接收人员，不自动发送给全体员工或仅默认发送店长。
- 门店自定义管理岗位由上级授予发送通知权限后，可以通知本店员工；普通店员不能发送通知。
- 商家老板及获得上级授权的商家账号，可以向其授权范围内的门店人员发送通知。
- 选择具体人员不扩大发送人的商家、门店及岗位授权范围；后端必须逐一校验，前端筛选不能替代权限检查。

## 初版建议

站内文字通知，含标题、正文、发送人、发送时间、收件人、已读时间。单独存储每个收件人的阅读状态；收件人按账号持久化，避免后续成员变化使历史通知串号。发送前选择具体账号，允许筛选商家、门店；是否支持全部商家或全部门店批量选择待实施时核对界面和性能。

后端接口建议：可选接收人查询、发送、收件箱分页、详情、已读、未读数量、已发送分页。列表、详情和已读仅允许收件账号访问；已发送仅允许发送人访问。服务端根据实际账号身份、商家归属、门店绑定和授予的发送权限重新校验每个收件人，禁止越商家、越门店、同级或向上级发送；拒绝整批非法请求，不只依赖前端过滤。重试需避免重复发送，消息长度、分页和接收人数设置上限。具体 URL、字段和错误码待实现后依据实际代码编写，不将草案当作已交付契约。

管理网页建议提供收件箱、未读提示及在有权限时显示发送入口；复用当前风格和岗位权限体系。运营和商家向门店发送时由发送人选择具体人员；禁用账号处理、普通店员不能发送给同店员工；店长可通知本店员工，其他自定义岗位是否属于可发送岗位须结合实际岗位权限和管理职责判定，不能仅根据门店账号类型放行。

## 现有项目核对

`WorkspaceAuthorization` 提供账号类型、岗位权限、可访问门店及门店绑定检查；`WorkspaceInitializer` 管理下级菜单和授权初始化。接入新增权限时不得因重启自动扩大既有商家或岗位授权。现有后端 `WorkspaceManagementService.java` 存在未提交修改，应保留。运营接口与商家／门店接口有不同认证路径，必须分别验证且避免权限绕过。

## 需要验证

运营跨级通知门店、商家只通知自身授权门店、店长只通知本店员工；跨商家、跨门店、同级或上级接收被拒；收件人只能读取／修改自己的消息；重复请求幂等；已读隔离；未授权账号不能发送；权限收回后不能继续发送。管理端需验证实际账号操作与空状态。移动端只交付经核实的接口文档，不修改其代码。
