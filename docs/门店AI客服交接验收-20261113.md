# 门店AI客服交接验收

本次仅后端源码、迁移和契约；未改Web或移动端，未推送，未操作Docker，未迁移业务开发库或重启现有服务。

## 实现

- presence以账号+客户端UUID隔离设备，持久化90秒租约，返回30秒心跳周期；一设备离线不影响其他设备。StoreChatAccess.staff(chat:reply)同时核验chat:view、门店身份及账号/门店范围，心跳不调用模型。
- return-to-ai仅当前接待者，复用requestId/version幂等；检查门店开关、平台控制、模型配置/worker及额度，未满足保持原状态。额度只在实际AI受理时消耗。
- humanRequested与AI/WAITING/HUMAN/CLOSED分开保存。转人工时AI可以先协助；离线交接始终保留人工待办；关闭/成功接管/主动交回清除待办。
- detail追加在线、AI可用性与原因、接待文案、交回权限和canManageSettings；page追加humanRequested、receptionText。配置权限仍为门店级chat:manage。
- 15秒巡检人工会话，最后一个有效租约过期后自动转AI或WAITING。自动接管关闭时只转WAITING。心跳恢复不抢回接待，CLOSED不重开。
- 接管无租约时建立一次90秒临时租约；旧接管请求兼容，前端必须持续上报独立会话心跳才会继续在线。
- 续答选择本轮最新未被AI/人工回答的顾客消息；无待答消息不调用模型。复用消息唯一任务，RUNNING旧版本任务先抑制结果再重新排队，避免旧回复被新版本冒用。写入锁顺序统一为会话后任务。
- 模型故障/资料改变/平台关闭等回复失败进入WAITING并保留待办。AI生成后人工接管时，版本屏障阻止迟到回复写入。

## 实测

日志 logs/test/chat-handoff-integration-20261113.log：27项，0失败、0错误、0跳过。

- 3项真实隔离MySQL集成：双设备主动离线及HTTP交回幂等；强制租约过期且自动接管关闭、恢复心跳不抢回、关闭不重开；模型生成中接管再交回、旧输出取消、重新排队后仅一条AI回复。
- 7项状态单测：非接待者拒绝、额度不足保持状态、转人工保留AI待办、未答续答、自动开关关闭、另一设备在线不交接、旧任务运行中不被复用、已答消息不重答（部分在同一测试内）。
- 其余覆盖配置兼容、已读状态、AI可用性原因及平台额度控制。
- 迁移在隔离库重复执行成功。测试中模型mock，无付费调用。数据库仅perkly_ai_regression_20261106；首次验证的DDL在事务夹具后执行，可能保留少量feat_前缀测试账号/门店；后续已调整为夹具创建前迁移，避免重复遗留，不涉及业务库。
