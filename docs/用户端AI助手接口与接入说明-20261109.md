# 用户端 AI 助手第一批接口

日期：2026-11-09。本文描述实际新增的独立后端代码；两个移动端尚未接入。管理端 CouponAssistantService 未修改。

## 身份与能力

全部接口要求当前有效 APP 用户 Token，游客、运营账号、商家账号不得使用。用户 ID 只从服务端登录身份读取；请求无 customerId/userId 字段。查券包与购券订单再次经过现有业务服务的归属校验。

支持找公开门店、找当前可领购券、解释公开券规则或本人历史券快照、查看自己的券和购券订单。只有查询与页面引导，不代领券、下单、支付、取消或执行 SQL。此处订单是购券订单，不包含消费账单。

## POST /app/ai/assistant/chat

请求头沿用项目 Authorization Token。首次请求示例：

```json
{"message":"福州有没有便宜的咖啡券"}
```

后续沿用 sessionId，无需重传城市、预算、偏好；用户说改城市、改付费时由意图提取及条件合并更新。定位是可选的 GCJ-02 坐标，不得用猜测值。例：

```json
{
  "sessionId":"服务端返回的UUID",
  "message":"只看付费的，购券价不超过20元",
  "location":{"longitude":119.30,"latitude":26.08}
}
```

从卡片进入解释，传真实种类及 ID。WALLET 的 id 是本人持券 ID，不是券模板 ID：

```json
{"sessionId":"服务端返回的UUID","message":"这张券怎么用","target":{"kind":"WALLET","id":123}}
```

字段：message 必填，1～1500 字；sessionId 可选；location 可选；target 可选，kind 为 COUPON/STORE/WALLET/ORDER。规则解释仅支持 COUPON/WALLET；券包、订单详情支持对应 target。跨用户 target 不会返回记录。

响应为既有 `R` 包装，成功 code=1000。以下是结构示例，记录内容与 ID 仅作演示，前端不可硬编码：

```json
{
  "code":1000,
  "message":"success",
  "data":{
    "sessionId":"服务端生成的UUID",
    "message":"找到了符合条件的券，购券价格见卡片。",
    "cards":[{
      "kind":"COUPON","id":123,"title":"咖啡代金券","merchantName":"示例咖啡店",
      "cover":"/upload/example.jpg","statusText":"可领购","priceCents":500,
      "purchasable":true,"destination":"COUPON_DETAIL",
      "facts":[{"label":"购券价格","value":"5.00元"},{"label":"抵扣金额","value":"10.00元"}]
    }],
    "suggestions":["推荐便宜的券","看看我的券","查看我的订单"],
    "conditions":{"area":"福州","keyword":"咖啡","priceMode":"PAID","maxPriceCents":2000,"spendBudgetCents":null,"cheap":true,"nearby":false},
    "degraded":false,"partial":false
  }
}
```

金额 priceCents/maxPriceCents/spendBudgetCents 均为**分**。免费 priceCents=0，不可按 falsy 判成未知；null 才是没有金额。ORDER 的 priceCents 是订单总金额。消费预算只用于过滤起用门槛，不等于购券价格或最终消费费用。

| destination | id 含义 | 前端动作 |
|---|---|---|
| STORE_DETAIL | 门店 ID | 打开已有门店详情 |
| COUPON_DETAIL | 券模板 ID | 打开已有优惠券详情，领购仍由原业务流程确认 |
| WALLET_DETAIL | 本人持券 ID | 打开已有我的券详情 |
| ORDER_DETAIL | 本人购券订单 ID | 打开已有订单详情 |

destination 是稳定业务目的地，不是写死的页面路由。前端维护映射；只使用服务端卡片 ID，不从自然语言抽取跳转参数。facts 用于可读展示；禁止将模型文本当 HTML、脚本或支付指令。历史券卡片 purchasable=false；本人券码及二维码不会进入助手响应和模型上下文，展示券码仍走原详情接口。

degraded=true 表示模型故障：意图阶段失败没有执行业务查询；回复组织失败会保留已查到的真实卡片并用后端说明兜底。请保留卡片和重试入口，不白屏。

## DELETE /app/ai/assistant/session?sessionId=...

仅允许当前会话所有者清除，返回既有成功包装。不存在、过期或其他用户会话返回业务 code=404；前端清除本地 sessionId 后重新开始。退出登录和切换账号必须清除本地会话 ID 与卡片。

服务端会话仅在当前进程内存保存，最多2000个，30分钟未访问过期，保留最近6轮消息，不建立长期画像。后端重启或多实例未配置粘性会话时，可能需要重建会话。清除不会删除真实券或订单。

## 当前查询边界

- 门店/券复用公开展示规则；券额外排除已结束、售罄、未开始及本人领购次数已满的记录。下架券不推荐，本人已有的券仍能按快照解释。
- 没有位置时按用户提供的区域地址匹配；没有区域则展示公开候选，不声称“附近”。仅要求附近且城市/位置都缺失时才询问位置或区域。
- 有位置且要求附近时筛选10公里内，缺经纬度的门店不参与附近结果。区域目前是地址包含匹配，并非行政区编码检索。
- 一次返回最多8张卡片，私有列表为最近8条，可按状态筛选；不支持私有列表按商品名、时间区间、金额筛选。更多进入原列表页。
- 公开查询为有界扫描，最多20页×100条；低价排序针对本次扫描到的候选。partial=true 表示截断或仍有更多卡片，不能展示“全平台最低价”或断言平台没有结果。用户量扩大后应将价格/区域筛选和排序下推到统一业务查询。
- 查询时状态不是库存承诺；真正领购仍以原接口实时校验为准。

## 总开发最小集成契约（尚待接入）

共享 AI 配置与管理控制台由总开发维护，本批没有改动 AiSettingsService/AiProperties/控制台。

新增接口 `com.cool.modules.ai.app.UserAssistantPolicy.checkAndConsume(Long customerId)`。总开发提供一个 Spring Bean 实现即可：

1. 检查独立的用户助手 enabled 开关。关闭时抛 CoolException，业务 code=503。
2. 检查用户维度的限额。默认**启用功能且关闭次数限制**，不限次时直接放行。
3. 若配置限额，以用户 ID + 业务日期原子计数；达到上限抛 code=429。不要复用商家图片额度或把0误解释为关闭AI。
4. 每个已校验登录身份的 chat 在调用模型前调用一次；含模型失败尝试。若需要成功计费或失败返还，可扩展契约后统一实现，当前不是成功次数计费。

未注入 Policy Bean 时本批约定是启用且不限次；因此控制台开关/额度**尚未集成验收**，不要宣称已由控制台控制。模型连接复用现有 AiProperties（BAILIAN_API_KEY、baseUrl、textModel），没有另建密钥配置，没有依赖管理端 CouponAssistantService。
